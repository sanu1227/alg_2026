
# Week 9: Graphs, Minimum Spanning Trees, and Shortest Paths (9주차: 그래프, 최소 신장 트리와 최단 경로)

기존 목록의 92개 용어를 순서대로 정리한 조사 자료이다. 용어는 굵게, 설명은 일반 서체로 구분했다. `n = |V|`는 정점 수, `m = |E|`는 간선 수, `c`는 연결 요소 수이다.

## Graph Basics (그래프 기초)

- **graph (그래프)**: 정점 집합 `V`와 간선 집합 `E`로 대상과 연결 관계를 나타내는 자료 구조이다. `G = (V, E)`로 표현한다. 도시를 정점, 도시 사이의 도로를 간선으로 표현할 수 있다.
- **vertex (정점)**: 그래프에서 대상을 나타내는 점. 복수형은 vertices이며, 수업 예제에서는 도시가 정점에 해당함
- **edge (간선)**: 두 정점 사이의 연결. 수업 예제에서는 도시 사이의 도로에 해당함
- **endpoint (끝점)**: 간선 양 끝에 있는 정점. 간선 `(u, v)`의 끝점은 `u`와 `v`
- **adjacent vertices (인접 정점)**: 하나의 간선으로 직접 연결된 두 정점
- **neighbor (이웃 정점)**: 특정 정점과 인접한 정점
- **degree (차수)**: 무방향 그래프에서 한 정점에 연결된 간선 끝의 수이다. 자기 루프는 같은 정점에 양 끝이 닿으므로 두 번 센다. 방향 그래프에서는 들어오는 간선 수인 진입 차수와 나가는 간선 수인 진출 차수를 구분한다.
- **undirected graph (무방향 그래프)**: 간선에 방향이 없어 `u`와 `v` 사이를 양방향으로 연결한 그래프. 이번 MST의 대상
- **directed graph (방향 그래프)**: 간선에 방향이 있어 `u -> v`와 `v -> u`를 구별하는 그래프
- **weighted graph (가중 그래프)**: 각 간선에 거리나 비용 같은 수치가 주어진 그래프
- **weight (가중치)**: 간선에 부여된 값. `(u, v, w)`에서 `w`는 두 정점을 연결하는 비용
- **drawing position (그림 배치 좌표)**: 정점을 화면에 그리기 위한 좌표이다. 이미 만들어진 그래프의 배치만 바꾸면 연결 관계와 저장된 가중치는 바뀌지 않는다. 데이터를 만들 때 거리 계산에 쓰는 좌표와 화면 표시용 좌표의 역할을 구분해야 한다.
- **distance-based weight (거리 기반 가중치)**: 두 지점 사이의 거리로 정한 간선 비용이다. 평면 좌표가 `(x1, y1)`, `(x2, y2)`이면 직선거리는 Python 수식으로 `sqrt((x2-x1)**2 + (y2-y1)**2)`이다. 예를 들어 `(0, 0)`과 `(3, 4)`의 거리는 5이다. 직선거리를 반올림해 가중치로 사용할 수도 있다. 이런 거리 기반 비용은 실제 도로 주행거리와는 다르다.
- **connection radius (연결 반경)**: 거리로 간선을 생성할 때 사용하는 최대 연결 거리이다. 예를 들어 반경이 10이면 거리가 10 이하인 도시 쌍만 연결한다. 반경이 작으면 간선이 줄어들고 그래프가 여러 연결 요소로 나뉠 수 있다.
- **edge intersection in a drawing (그림에서의 간선 교차)**: 두 간선이 화면에서 교차하는 것. 교차점이 정점으로 등록되어 있지 않으면 그곳에서 다른 간선으로 갈아탈 수 없으며, 그림에서 교차한다는 이유만으로 사이클이 생기는 것도 아님
- **path (경로)**: 간선을 따라 정점들을 연결한 순서. 단순 경로는 정점을 반복하지 않음
- **cycle (사이클)**: 출발 정점으로 되돌아오는 닫힌 경로. 단순 무방향 그래프에서는 시작과 끝 외의 정점을 반복하지 않고 간선도 재사용하지 않음
- **connected graph (연결 그래프)**: 임의의 두 정점 사이에 경로가 존재하는 무방향 그래프
- **connected component (연결 요소)**: 서로 경로로 연결된 정점들의 최대 집합. 다른 연결 요소와는 간선으로 이어져 있지 않음
- **isolated vertex (고립된 정점)**: 연결된 간선이 하나도 없는 정점. 인접 목록에서는 빈 이웃 목록을 가지며, 혼자서 하나의 연결 요소를 이룸
- **sparse graph (희소 그래프)**: 가능한 간선 수에 비해 실제 간선이 적은 그래프이다. 정점 수 `n`에 비례하는 정도의 간선을 가진 그래프가 대표적인 예이다. 보통 인접 목록으로 표현하면 공간을 절약할 수 있다.
- **dense graph (밀집 그래프)**: 가능한 정점 쌍 중 많은 쌍이 간선으로 연결된 그래프이다. 자기 루프와 중복 간선이 없는 무방향 그래프의 최대 간선 수는 `n(n-1)/2`이며, 밀집 그래프의 간선 수는 보통 `n^2`에 비례하는 규모이다.

### 예시: 인접 관계와 연결 요소

정점이 `A, B, C, D`이고 간선이 `A-B`, `B-C`라고 하자. `A`와 `C`는 직접 인접하지 않지만 `A, B, C` 순서의 경로로 연결된다. 차수는 `A=1`, `B=2`, `C=1`, `D=0`이다. 연결 요소는 `{A, B, C}`와 `{D}`의 두 개이며, `D`는 고립된 정점이다.

그래프의 인접 관계, 경로, 연결 요소, 트리의 정의는 [Princeton Algorithms의 Undirected Graphs](https://algs4.cs.princeton.edu/41graph/index.php)를 참고했다. 그림의 배치와 연결 관계를 구분하는 설명은 수업 파일의 표현에 맞췄다.

## Graph Representation (그래프 표현)

- **vertex index (정점 index)**: 정점에 부여한 `0`부터 `n - 1`까지의 번호. 도시 이름과 배열 위치를 구별함
- **edge list (간선 목록)**: `[(u, v, w), ...]`처럼 모든 간선을 나열한 표현. Kruskal에서 가중치순으로 정렬하기 편리함
- **adjacency matrix (인접 행렬)**: `n x n` 배열의 `matrix[u][v]`에 두 정점 사이의 연결 여부 또는 가중치를 저장하는 표현
- **absent edge (존재하지 않는 간선)**: 두 정점을 직접 잇는 간선이 없는 상태이다. 가중치 행렬에서는 `None`이나 무한대 등으로 표시한다. 가중치 0인 간선도 유효할 수 있으므로, 이 경우 0을 간선 없음의 표시로 쓰면 구별할 수 없다.
- **symmetric matrix (대칭 행렬)**: 무방향 그래프에서는 `matrix[u][v] == matrix[v][u]`가 되는 성질
- **adjacency list (인접 목록)**: 각 정점에 대해 직접 연결된 이웃과 가중치만 저장하는 표현
- **dictionary-based adjacency list (딕셔너리 기반 인접 목록)**: `graph[u][v] = w`처럼 정점마다 딕셔너리로 이웃과 가중치를 저장하는 표현이다. 두 index를 사용해도 모든 정점 쌍의 칸을 저장하지 않으므로 인접 행렬이 아니다. 같은 `u, v`에 다시 대입하면 기존 값이 바뀌므로 여러 평행 간선을 별도로 저장하려면 다른 표현이 필요하다.
- **bidirectional insertion (양방향 등록)**: 무방향 간선 `(u, v, w)`를 인접 목록에 넣을 때 `graph[u][v] = w`와 `graph[v][u] = w`를 함께 저장하는 것
- **neighbor iteration (이웃 순회)**: `for v, w in graph[u].items():`로 정점 `u`의 이웃과 가중치를 함께 읽는 것
- **representation cost (표현 비용)**: 정점 수 `n`, 간선 수 `m`일 때 인접 행렬의 공간 복잡도는 `O(n^2)`, 인접 목록은 `O(n + m)`이다. 무방향 간선을 양쪽에 저장하면 간선 항목은 `2m`개지만 상수 배는 생략하므로 점근적 공간 복잡도는 같다.
- **edge lookup (간선 조회)**: 두 정점 사이에 직접 연결된 간선이 있는지 확인하는 연산이다. 인접 행렬은 `O(1)`, 딕셔너리 기반 인접 목록은 평균 `O(1)`에 조회한다. 일반 리스트 기반 인접 목록은 정점 `u`의 이웃을 찾아야 하므로 최악에 `O(degree(u))`가 걸린다.

### 예시: 같은 그래프의 세 가지 표현

정점 `0, 1, 2`에서 간선이 `(0, 1, 4)`, `(1, 2, 2)`인 무방향 가중 그래프를 생각한다.

```text
간선 목록
[(0, 1, 4), (1, 2, 2)]

인접 행렬: None은 직접 연결된 간선이 없다는 뜻
[[None,    4, None],
 [   4, None,    2],
 [None,    2, None]]

딕셔너리 기반 인접 목록
{0: {1: 4}, 1: {0: 4, 2: 2}, 2: {1: 2}}
```

여기서는 자기 루프가 없으므로 행렬 대각선도 `None`으로 표시했다. `graph[1].items()`를 순회하면 `(0, 4)`와 `(2, 2)`를 읽는다. 무방향 간선은 인접 목록 양쪽에 저장하지만 실제 간선 수 `m`은 2이다. 현재 `ch4_0_graph.py`도 정점별 빈 딕셔너리를 만들고 양방향으로 간선을 등록한다.

인접 목록의 구성과 `O(n + m)` 공간 사용은 [Princeton의 Graph 자료 구조 설명](https://algs4.cs.princeton.edu/code/javadoc/edu/princeton/cs/algs4/Graph.html)에서 확인할 수 있다.

## Trees and MST (트리와 최소 신장 트리)

- **tree (트리)**: 연결되어 있고 사이클이 없는 무방향 그래프. 정점이 `n`개이면 간선은 `n - 1`개
- **forest (포리스트)**: 사이클이 없는 무방향 그래프. 여러 트리로 나뉘어 있어도 됨
- **forest edge count (포리스트의 간선 수)**: 정점이 `n`개이고 연결 요소가 `c`개인 포리스트의 간선 수는 `n - c`개. 사이클 없이 간선을 하나 추가해 서로 다른 두 트리를 연결할 때마다 연결 요소 수가 하나 줄어듦
- **spanning tree (신장 트리)**: 원래 그래프의 모든 정점을 포함하면서 원래 간선 중 일부를 선택해 만든 트리
- **minimum spanning tree (최소 신장 트리, MST)**: 연결된 무방향 가중 그래프에서 모든 정점을 포함하는 신장 트리 중 간선 가중치 합이 최소인 트리이다. 정점이 `n`개이면 간선은 `n-1`개이며 사이클이 없다. 간선 가중치가 0이거나 음수여도 MST를 정의할 수 있다.
- **total weight (가중치 합)**: 선택한 간선들의 가중치를 더한 값. MST가 최소화하려는 대상
- **minimum spanning forest (최소 신장 포리스트)**: 연결되지 않은 그래프에서 각 연결 요소의 MST를 모은 결과. 전체 정점을 잇는 하나의 신장 트리는 만들 수 없음
- **non-unique MST (유일하지 않은 MST)**: 최소 가중치 합이 같은 신장 트리가 여러 개 존재하는 경우이다. 모든 간선 가중치가 서로 다르면 MST는 유일하다. 그러나 같은 가중치가 있다고 해서 반드시 MST가 여러 개인 것은 아니다.
- **shortest path (최단 경로)**: 두 정점을 잇는 경로 중 간선 가중치 합이 가장 작은 경로이다. MST는 전체 정점을 연결하는 총비용을 최소화하므로, MST 안에서 두 정점을 잇는 경로가 원래 그래프의 최단 경로라는 보장은 없다.

### 예시: MST와 최단 경로는 목적이 다르다

삼각형 그래프의 간선 비용이 `A-B=2`, `B-C=2`, `A-C=3`이라고 하자. MST는 `A-B`와 `B-C`를 선택하며 총비용은 4이다. 그러나 원래 그래프에서 `A`에서 `C`까지의 최단 경로는 비용 3인 직접 간선이다. MST 내부의 `A, B, C` 경로는 비용 4이므로 최단 경로가 아니다.

세 간선의 비용이 모두 1인 삼각형에서는 어느 두 간선을 선택해도 총비용 2인 MST가 된다. 반면 원래 그래프가 이미 트리라면 같은 가중치가 있어도 선택 가능한 신장 트리는 하나이다.

MST의 정의, 가중치 동률과 유일성, Kruskal과 Prim의 원리는 [Princeton Algorithms의 Minimum Spanning Trees](https://algs4.cs.princeton.edu/43mst/)를 참고했다.

## Greedy Strategy (탐욕 전략)

- **greedy algorithm (탐욕 알고리즘)**: 매 단계에서 현재 선택 기준에 가장 적합한 후보를 고르고 그 선택을 누적하는 알고리즘이다. 보통 앞선 선택을 되돌리지 않는다. 모든 문제에서 최적해를 보장하지 않으며, MST에서는 컷 성질로 선택의 정당성을 설명할 수 있다.
- **local choice (국소적 선택)**: 현재 고려하는 후보 중 비용이 가장 작은 간선 등을 선택하는 것
- **global optimum (전체 최적해)**: 모든 가능한 해 중 목적값이 가장 좋은 해. MST에서는 전체 가중치 합이 최소인 신장 트리
- **safe edge (안전한 간선)**: 현재 선택한 간선 집합 `A`와 새 간선을 모두 포함하는 MST가 존재하도록 추가할 수 있는 간선이다. 단순히 사이클을 만들지 않는다는 조건만으로는 안전한 간선이라고 할 수 없다.
- **cut (컷)**: 전체 정점 집합 `V`를 겹치지 않는 두 부분 `S`와 `V-S`로 나눈 것이다. 여기서는 두 부분이 모두 비어 있지 않은 컷을 고려한다. 화면에서 선을 긋는 위치보다 정점들이 어느 집합에 속하는지가 중요하다.
- **crossing edge (컷을 가로지르는 간선)**: 양 끝점이 컷의 서로 다른 집합에 속하는 간선
- **cut property (컷 성질)**: 현재 간선 집합 `A`가 어떤 MST의 일부이고, `A`의 간선이 하나도 가로지르지 않는 컷을 생각한다. 그 컷을 가로지르는 최소 가중치 간선은 `A`에 안전하게 추가할 수 있다. 최소 가중치가 동률이면 선택한 간선을 포함하는 MST가 존재한다는 뜻이며, 모든 MST에 그 간선이 들어간다는 뜻은 아니다.
- **cycle avoidance (사이클 방지)**: 트리에는 사이클이 없어야 하므로 선택한 간선들에 사이클을 만드는 간선은 추가하지 않는 것

### 예시: 컷을 가로지르는 가장 가벼운 간선

현재 선택한 간선들이 어떤 MST의 일부라고 하자. 정점 집합을 `{A, B}`와 `{C, D}`로 나누고, 이미 선택한 간선은 양쪽 집합 내부에만 있다고 가정한다. 이 컷을 가로지르는 간선이 `A-C=5`, `B-C=2`, `B-D=4`이면 `B-C`를 안전하게 추가할 수 있다.

여기서 안전하다는 것은 기존 선택과 새 간선을 함께 포함하는 MST가 존재한다는 뜻이다. 사이클만 없으면 충분한 것은 아니다. 예를 들어 비용이 `1, 2, 100`인 삼각형에서 처음에 비용 100인 간선을 골라도 즉시 사이클은 생기지 않지만 MST를 만들 수는 없게 된다.

안전한 간선의 전제와 컷 성질은 [University of Hawaiʻi의 Safe Edge Theorem](https://courses.ics.hawaii.edu/ics311_f26/Notes/Topic-17.html)에서 확인했다.

## Kruskal's Algorithm (크루스칼 알고리즘)

- **Kruskal's algorithm (크루스칼 알고리즘)**: 전체 간선을 가중치가 작은 순서로 검사하면서 서로 다른 연결 요소를 잇는 간선만 선택하는 MST 알고리즘
- **edge sorting (간선 정렬)**: 간선의 가중치를 기준으로 오름차순 정렬하는 과정이다. `(u, v, w)` 형식이면 `sorted(edges, key=lambda edge: edge[2])`로 세 번째 값 `w`를 비교한다. `sorted()`는 새 리스트를 반환하므로 원본 입력 목록의 순서는 유지된다.
- **tie-breaking (동률 처리)**: 가중치가 같은 후보 사이에서 처리 순서를 정하는 것이다. Python 정렬은 안정 정렬이므로 가중치만 key로 지정하면 같은 가중치끼리 입력 순서를 유지한다. 동률 처리에 따라 MST의 간선 구성은 달라질 수 있지만 최소 총비용은 같다.
- **candidate edge (후보 간선)**: 정렬된 목록에서 선택 여부를 검사할 간선. 아직 검사하지 않은 간선과 검사 후 제외한 간선을 구별함
- **accepted edge (선택한 간선)**: 현재 서로 다른 집합을 연결하여 MST 구성에 포함한 간선. 선택 개수와 누적 비용에 포함함
- **rejected edge (제외한 간선)**: 두 끝점이 이미 같은 집합에 있어 사이클을 만들기 때문에 건너뛴 간선. 선택 개수와 누적 비용에 포함하지 않음
- **component merging (연결 요소 합치기)**: 처음에는 각 정점을 별도의 집합으로 두고, 간선을 선택할 때 두 집합을 합치는 것
- **disjoint set (서로소 집합)**: 서로 공통 원소가 없는 집합들을 뜻한다. 알고리즘에서는 이러한 집합들의 소속 관계를 관리하는 자료 구조를 가리키기도 한다. 예를 들어 `{0, 1}`과 `{2, 3}`은 서로소 집합이다.
- **Union-Find (합치기와 대표 찾기)**: 원소가 속한 집합의 대표를 찾는 `find`와 두 집합을 합치는 `union`을 제공하는 자료 구조. 수업 코드에서는 대표 찾기를 `getRoot`로 구현함
- **representative / root (대표 / 루트)**: 집합을 구별하는 대표 원소. MST 자체의 트리에서 말하는 부모나 루트와 구별함
- **parent array (부모 배열)**: Union-Find에서 각 원소의 부모를 저장한 배열. 수업에서는 `roots = [i for i in range(n)]`으로 초기화함. `roots[i]`가 항상 최종 루트인 것은 아니며, 값을 따라가 자기 자신을 가리키는 정점에 도달하면 그 정점이 루트임
- **Union-Find tree versus MST (집합 관리 트리와 최소 신장 트리의 차이)**: `roots`의 부모 연결은 같은 집합임을 관리하기 위한 관계임. 두 정점을 부모와 자식으로 기록했다고 해서 원래 그래프의 그 간선을 MST로 선택한 것은 아님. 실제 선택 간선은 `mst`에 따로 저장함
- **find (대표 찾기)**: 부모를 따라가며 원소가 속한 집합의 대표를 찾는 연산. `getRoot(roots[vertex])`로 재귀 호출하며, 경로 압축 없이 대표만 반환해도 올바른 루트를 구할 수 있음
- **base case (기저 조건)**: `roots[vertex] == vertex`이면 대표에 도달했으므로 더 재귀 호출하지 않고 그 정점을 반환하는 조건
- **recursive descent (재귀 호출 진입)**: 현재 정점의 부모를 인자로 다음 `getRoot`를 호출하며 루트 쪽으로 들어가는 과정. 이때 바깥 호출들은 반환값을 기다림
- **recursion unwinding (재귀 호출 복귀)**: 루트에서 구한 반환값이 기다리던 호출들로 역순으로 돌아오는 과정. 경로 압축 버전에서는 이 시점에 각 호출의 `roots[vertex]`를 기록함
- **path compression (경로 압축)**: 대표를 찾은 뒤 재귀 호출에서 돌아오면서 `roots[vertex]`를 반환받은 대표로 바꾸어 이후 탐색을 짧게 만드는 기법. 집합의 구성이나 이미 선택한 MST 간선을 바꾸지는 않음
- **shortcut (바로 가기)**: 중간 부모들을 거치지 않고 대표를 직접 가리키도록 기록한 연결. 리턴하면서 배열에 기록하는 단계가 단순 대표 반환과의 차이임
- **union (집합 합치기)**: 서로 다른 두 집합의 대표 중 하나를 다른 대표 아래에 연결하는 연산
- **representative selection rule (대표 선택 규칙)**: union할 때 어느 대표를 남길지 정하는 규칙이다. 현재 수업 코드는 작은 번호를 대표로 남긴다. 이는 간선 가중치와 관계없는 규칙이며 트리 높이를 균형 있게 유지한다는 보장은 없다. 성능을 개선할 때는 집합 크기나 트리 높이의 상한인 rank를 기준으로 합치기도 한다.
- **cycle detection (사이클 판정)**: `getRoot(u) == getRoot(v)`이면 이미 선택한 간선들로 두 정점 사이에 경로가 있으므로 간선 `(u, v)`를 추가하면 사이클이 생김
- **edge acceptance and union (간선 확정과 집합 합치기)**: 서로 다른 집합의 두 정점을 잇는 간선을 MST 후보에 확정하고 비용을 누적한 다음, 두 대표를 union하여 이후의 사이클 검사에 반영함
- **loop invariant (반복 불변식)**: 반복문의 각 단계 전후에 유지되는 성질이다. Kruskal에서는 선택한 간선들이 사이클 없는 포리스트이고 Union-Find의 집합들이 그 연결 요소와 일치해야 한다. 또한 선택한 간선 집합 전체를 포함하는 MST가 존재해야 한다. 간선 선택 뒤 union을 생략하면 연결 요소의 일치가 깨진다.
- **stopping condition (종료 조건)**: 연결된 그래프에서 선택한 간선 수가 `n-1`개이면 MST가 완성된다. 그보다 적은 상태로 모든 후보를 검사했다면 전체 신장 트리는 존재하지 않고 최소 신장 포리스트가 남는다. 정점이 하나이면 간선 0개로 이미 트리이다.
- **examined versus accepted edge count (검사한 간선 수와 선택한 간선 수)**: 제외한 간선도 검사 횟수에는 포함됨. 종료 기준은 반복 횟수나 검사 횟수가 아니라 실제 선택한 간선 `n - 1`개임
- **time complexity (시간 복잡도)**: 간선 정렬에 `O(m log m)`이 걸린다. 경로 압축과 크기 또는 rank 기반 union을 사용하는 표준 Kruskal은 연결 그래프에서 전체 `O(m log m)`이다. 현재 수업 코드는 경로 압축과 작은 번호 우선 union을 사용하므로, 두 최적화를 모두 적용한 Union-Find의 분석과 구분한다. 여기서 알고리즘 복잡도는 화면 표시나 사용자의 대기 시간을 제외한다.

### 예시: Kruskal의 선택과 제외

정점이 `A, B, C, D`이고 간선 비용이 `A-B=1`, `B-C=2`, `A-C=3`, `C-D=4`, `B-D=5`라고 하자.

1. `A-B=1`을 선택하고 두 정점의 집합을 합친다.
2. `B-C=2`를 선택하면 `{A, B, C}`가 하나의 집합이 된다.
3. `A-C=3`은 두 끝점이 같은 집합이므로 제외한다. 추가하면 `A, B, C, A` 사이클이 생긴다.
4. `C-D=4`를 선택하면 모든 정점이 연결된다. 간선을 `4-1=3`개 선택했으므로 종료한다.

검사한 간선은 4개이고 선택한 간선은 3개이다. 총비용은 `1+2+4=7`이다. 비용 5인 후보는 검사하지 않아도 된다. 이처럼 종료 조건은 검사 횟수가 아니라 실제 선택한 간선 수이다.

Python의 `sorted()`와 동일 key의 입력 순서 유지는 [Python 공식 정렬 안내](https://docs.python.org/3/howto/sorting.html)를 참고했다. 정렬 후에는 현재 코드처럼 `for`문으로 순회하면 된다. 현재 길이가 `k`인 리스트의 `pop(0)`은 남은 원소를 이동시키므로 한 번에 `O(k)`이고, 길이 `m`의 리스트를 앞에서 반복해서 비우면 합계 `O(m^2)`가 된다. 이 이동 비용은 [Python 공식 collections 문서](https://docs.python.org/3/library/collections.html#collections.deque)에 설명되어 있다.

### Return Only versus Path Compression (단순 반환과 경로 압축의 차이)

`roots = [0, 0, 1, 2]`에서 `getRoot(3)`은 `3 -> 2 -> 1 -> 0` 순서로 들어간 뒤 루트 `0`을 반환함.

- **return only (단순 반환)**: 배열은 `[0, 0, 1, 2]` 그대로이며, 다시 호출하면 같은 경로를 따라감. 느릴 수 있지만 잘못된 루트를 구하는 것은 아님
- **return with shortcut (바로 가기를 기록하며 반환)**: 리턴하면서 배열이 `[0, 0, 0, 0]`으로 바뀜. 이후 `getRoot(3)`은 `3 -> 0`으로 루트에 도달함
- **unchanged result (변하지 않는 결과)**: 두 버전의 반환값과 집합 구성은 같음. 달라지는 것은 집합을 표현하는 부모 연결과 이후 탐색에 필요한 단계 수임

### 예시: 반환값과 배열 변경의 차이

`roots = [0, 0, 1, 2]`에서 `getRoot(3)`을 호출하면 다음 순서로 동작한다.

1. `getRoot(3)`이 `getRoot(2)`를 호출하고 반환을 기다린다.
2. `getRoot(2)`가 `getRoot(1)`을 호출하고 반환을 기다린다.
3. `getRoot(1)`이 `getRoot(0)`을 호출한다. `roots[0] == 0`이므로 0을 반환한다.
4. 복귀하면서 현재 코드의 `roots[vertex] = root`가 실행된다. `roots[1]`, `roots[2]`, `roots[3]`에 차례로 0이 기록된다.

최종 배열은 `[0, 0, 0, 0]`이고 반환값은 0이다. 대입 없이 `return root`만 해도 반환값은 0이지만 배열은 바뀌지 않는다. 다음 탐색의 경로를 줄이는 부분은 반환 자체가 아니라 부모 배열에 대표를 기록하는 대입이다.

경로 압축은 이번에 지나간 경로를 짧게 만든다. 모든 정점의 부모를 매번 한꺼번에 바꾸지는 않는다. 집합 소속과 이미 선택한 MST 간선은 그대로이다. 개념은 [Princeton의 Union-Find 강의 자료](https://algs4.cs.princeton.edu/lectures/keynote/15UnionFind.pdf)를, 변수와 재귀 호출 설명은 현재 `ch4_1_mst_kruskal.py`를 기준으로 확인했다.

## Prim's Algorithm (프림 알고리즘)

- **Prim's algorithm (프림 알고리즘)**: 한 정점에서 시작하여 현재 트리와 바깥 정점을 연결하는 가장 가벼운 간선을 반복해서 추가하는 MST 알고리즘
- **start vertex (시작 정점)**: 첫 트리를 이루는 정점. 연결된 그래프에서는 어느 정점에서 시작해도 MST를 구할 수 있으며, 동률 처리에 따라 선택 간선은 달라질 수 있음
- **selected vertices (선택된 정점)**: 현재 트리에 포함된 정점의 집합. 구현에서는 `completed` 같은 집합으로 관리할 수 있음
- **frontier (탐색 경계)**: 현재 트리에서 간선 하나로 연결할 수 있는 바깥 정점들
- **connection cost / key (연결 비용 / 키)**: 바깥 정점 `v`와 현재 트리 안의 정점을 직접 연결하는 간선 중 가장 작은 가중치이다. 연결 간선이 없으면 무한대로 둔다. `key[v] = min(w(u, v))`에서 `u`는 현재 트리의 정점이며, 시작점에서 `v`까지 누적한 거리가 아니다.
- **predecessor (이전 정점)**: 바깥 정점 `v`를 현재 가장 작은 간선 비용으로 연결해 주는 트리 안의 정점이다. `v`가 선택될 때 `(predecessor[v], v)`를 MST 간선으로 기록한다. 더 작은 연결 간선을 찾으면 key와 함께 갱신한다.
- **priority queue (우선순위 큐)**: 각 항목에 우선순위를 부여하고 가장 우선하는 항목부터 꺼내는 자료 구조이다. 정점별 비용을 관리하는 Prim에서는 연결 비용이 작은 정점이 먼저 나온다. 간선 자체를 후보로 저장하는 Prim 구현도 있다.
- **decrease-key (우선순위 감소)**: 큐에 이미 있는 후보의 우선순위 값을 더 작은 값으로 갱신하는 연산이다. Prim에서 새 정점과 연결된 간선의 비용이 기존 key보다 작으면 key와 이전 정점을 바꾼다.
- **minimum extraction (최솟값 추출)**: 우선순위 큐에서 최소 연결 비용의 정점을 꺼내 트리에 포함하는 것
- **heapdict (힙 딕셔너리)**: 딕셔너리 형태로 항목별 우선순위를 저장하는 외부 Python 패키지이다. `hd[v] = cost`로 우선순위를 등록하거나 변경하고, `hd.popitem()`으로 우선순위 값이 가장 작은 `(항목, 우선순위)`를 꺼낸다. Python 표준 라이브러리의 `heapq`와는 별도이다.
- **array-based Prim (배열 기반 프림)**: 현재 트리에 포함되지 않은 정점 중 key가 가장 작은 정점을 배열에서 선형 탐색으로 고르는 구현이다. 인접 행렬로 이웃을 확인하며 `n`번 확장하면 시간 복잡도는 `O(n^2)`이다.
- **heap-based Prim (힙 기반 프림)**: 인접 목록과 이진 힙을 사용하여 후보를 관리하는 구현이다. 정점별 key를 갱신하는 방식은 `O((n + m) log n)`이며, 연결 그래프에서는 보통 `O(m log n)`으로 나타낸다. 간선을 힙에 넣고 오래된 후보를 꺼낼 때 버리는 지연 방식은 `O(m log m)`으로 분석하므로 구현을 구분해야 한다.
- **Kruskal versus Prim (크루스칼과 프림 비교)**: Kruskal은 전체 간선 중 다음 간선을 골라 여러 트리를 합치고, Prim은 하나의 트리에서 바깥으로 확장함. 둘 다 MST를 구하지만 간선을 고르는 범위와 관리하는 자료 구조가 다름

### 예시: Prim의 key 갱신

앞의 네 정점 그래프에서 `A`로 시작한다. 처음에는 `B`의 연결 비용이 1, `C`의 연결 비용이 3이고 `D`는 아직 직접 연결할 수 없다. `B`를 선택하면 `B-C=2`를 이용할 수 있으므로 `C`의 key를 3에서 2로 바꾸고 이전 정점을 `B`로 기록한다. `D`의 key는 `B-D=5`로 5가 된다.

다음으로 `C`를 선택하면 `C-D=4`가 기존 값 5보다 작으므로 `D`의 key를 4로 바꾸고 이전 정점을 `C`로 기록한다. 최종 선택 간선은 `A-B`, `B-C`, `C-D`이고 총비용은 7이다. 이때 `C`의 key인 2는 `B-C` 간선 하나의 비용이며, `A`에서 `C`까지 선택한 경로의 누적 비용 3과 구별된다.

Kruskal은 전체 간선의 정렬 순서에 따라 여러 연결 요소를 합친다. Prim은 현재 트리와 바깥 정점 사이의 간선만 비교하며 하나의 트리를 확장한다. 연결되지 않은 그래프에서 Prim을 한 정점에서만 실행하면 해당 연결 요소까지만 처리되므로, 최소 신장 포리스트를 얻으려면 다른 미방문 연결 요소에서도 다시 시작해야 한다.

Prim의 후보 관리와 구현별 복잡도는 [Princeton의 Prim 설명](https://algs4.cs.princeton.edu/43mst/)을, `heapdict`의 우선순위 변경과 `popitem()` 동작은 [heapdict 공식 저장소](https://github.com/DanielStutzbach/heapdict)를 참고했다.

## Dijkstra's Algorithm (다익스트라 알고리즘)

- single-source shortest paths (단일 시작점 최단 경로): 하나의 시작점에서 도달 가능한 각 정점까지 가중치 합이 최소인 경로와 그 거리를 구하는 문제
- Dijkstra's algorithm (다익스트라 알고리즘): 간선 가중치가 0 이상인 그래프에서 누적 거리가 가장 작은 후보를 꺼내 최단 거리를 확정하고 이웃의 거리 후보를 갱신하는 탐욕 알고리즘
- path weight (경로 가중치): 경로를 따라 이동할 때 지나는 간선들의 가중치 합. 간선 하나의 가중치나 전체 트리의 간선 합과 구별함
- cumulative distance (누적 거리): 시작점에서 현재 정점까지의 경로 가중치. 현재 정점을 거쳐 이웃으로 가는 새 거리 후보는 `cost + edge_cost`
- relaxation (완화): 이웃까지의 기존 거리 후보보다 현재 정점을 거치는 경로가 더 짧으면 거리와 이전 정점을 함께 갱신하는 과정. 아직 후보가 없다면 새로 등록함
- settled vertex (확정 정점): 최소 거리 후보로 꺼내 최단 거리가 확정된 정점. 가중치가 0 이상이므로 아직 확정하지 않은 정점을 경유하여 더 짧아질 수 없음
- nonnegative edge weights (음수가 아닌 간선 가중치): Dijkstra의 거리 확정에 필요한 조건. 0은 허용하지만 음수는 허용하지 않음. Prim은 음수 가중치가 있어도 MST를 구할 수 있음
- distance array (거리 배열): 각 정점까지의 최단 거리를 저장하는 배열. 수업 구현은 확정 시 기록하며, 도달하지 못한 정점은 `float("inf")`로 남음
- predecessor array (이전 정점 배열): `previous[v]`에 최단 경로에서 정점 `v` 바로 앞의 정점을 기록한 배열. 거리만으로는 경로를 복원할 수 없으므로 경로 출력 단계에서 도입함
- path reconstruction (경로 복원): 목적지부터 이전 정점을 따라가며 시작점까지 역순으로 모은 뒤 뒤집어 실제 이동 순서로 만드는 것. 시작점의 이전 정점은 `None`
- unreachable vertex (도달 불가 정점): 시작점에서 경로가 없는 정점. 거리 무한대와 이전 정점 `None`으로 나타내며 단순히 비용이 큰 정점과 구별함
- shortest-path tree (최단 경로 트리): 도달 가능한 정점들의 이전 정점 연결을 모은 트리. 시작점부터 각 정점까지의 경로가 최단이지만 간선 가중치 합이 최소인 MST일 필요는 없음
- Prim versus Dijkstra (프림과 다익스트라 비교): Prim은 후보를 `edge_cost`로 평가하여 전체 연결 비용을 최소화하고, Dijkstra는 `cost + edge_cost`로 평가하여 시작점부터 각 정점까지의 경로 거리를 최소화함. 후보 관리 구조가 비슷해도 구하는 결과가 다름
- MST versus shortest-path example (최소 신장 트리와 최단 경로 예): A-B=2, B-C=2, A-C=3이면 MST는 A-B와 B-C로 총비용 4이지만 A에서 C까지의 최단 경로는 거리 3인 A-C임. A의 최단 경로 트리는 A-B와 A-C로 간선 합이 5여도 올바름
- heap-based Dijkstra (힙 기반 다익스트라): 인접 목록과 정점별 우선순위 갱신을 지원하는 이진 힙으로 구현하면 정점 수 n과 간선 수 m에 대해 `O((n + m) log n)`에 처리함. 시각화와 결과 출력 비용은 별도임
