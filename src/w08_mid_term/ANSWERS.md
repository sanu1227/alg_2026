## 1. Python 자료 구조

### 1번

**Python 리스트는 원소의 값을 변경할 수 있다.**

정답: O

해설: 리스트는 가변 객체이므로 생성한 뒤에도 원소를 교체하거나 추가·삭제할 수 있다. 예를 들어 `a = [10, 20]` 뒤에 `a[0] = 99`를 실행하면 `a`는 `[99, 20]`이 된다. 값을 바꾸어도 같은 리스트 객체를 사용한다.

### 2번

**비어 있지 않은 리스트에서 `array[-1]`은 첫 번째 원소를 가리킨다.**

정답: X

올바른 문장: 비어 있지 않은 리스트에서 `array[-1]`은 마지막 원소를 가리킨다.

해설: 음수 index는 리스트의 끝에서부터 센다. `-1`은 마지막 원소, `-2`는 끝에서 두 번째 원소이며 첫 번째 원소의 index는 `0`이다. 예를 들어 `[10, 20, 30][-1]`은 `30`이다. 빈 리스트에 `[-1]`로 접근하면 `IndexError`가 발생하므로 문제의 비어 있지 않다는 조건도 필요하다.

### 3번

**리스트의 슬라이스 `array[a:b]`는 시작 index `a`와 끝 index `b`를 모두 포함한다.**

정답: X

올바른 문장: 리스트의 슬라이스 `array[a:b]`는 시작 index `a`를 포함하고 끝 index `b`는 제외한다.

해설: 슬라이스는 시작 위치를 포함하고 끝 위치 바로 앞에서 멈춘다. 예를 들어 `[10, 20, 30, 40][1:3]`의 결과는 `[20, 30]`이며 index 3의 `40`은 포함되지 않는다. 일반적인 유효 범위에서 원소 수는 `b - a`이고, 끝을 제외하는 규칙 때문에 `[a:b]`와 `[b:c]`를 겹치지 않게 이어 쓸 수 있다.

### 4번

**`copied = original[:]`로 리스트를 복사하면 바깥 리스트는 새로 만들어지지만, 내부의 가변 객체는 공유될 수 있다.**

정답: O

해설: `original[:]`는 얕은 복사이다. 바깥 리스트만 새로 만들고 각 원소가 가리키는 객체는 공유한다. `original = [[1], [2]]`와 `copied = original[:]` 이후 `copied[0].append(9)`를 실행하면 `original[0]`도 `[1, 9]`가 된다. 반면 `copied[0] = [7]`처럼 복사본의 칸 자체를 교체하면 원본의 해당 칸은 바뀌지 않는다.

### 5번

**딕셔너리에서 `key in mapping`은 해당 값이 value에 있는지를 검사한다.**

정답: X

올바른 문장: 딕셔너리에서 `key in mapping`은 해당 key가 있는지를 검사한다.

해설: 딕셔너리에 직접 `in`을 적용하면 key를 검사한다. `mapping = {"name": "Kim"}`에서 `"name" in mapping`은 참이지만 `"Kim" in mapping`은 거짓이다. value를 검사하려면 `"Kim" in mapping.values()`를 사용한다.

### 6번

**`for key, value in mapping.items():`는 딕셔너리의 key와 value를 함께 순회하는 방법이다.**

정답: O

해설: `mapping.items()`를 순회하면 `(key, value)` 쌍을 하나씩 얻는다. `for key, value in ...`는 각 쌍의 두 항목을 변수에 풀어 담는다. 예를 들어 `{"A": 90}`를 순회하면 `key`는 `"A"`, `value`는 `90`이므로 별도의 `mapping[key]` 조회 없이 둘 다 사용할 수 있다.

### 7번

**집합은 중복 원소를 제거하는 데 사용할 수 있다.**

정답: O

해설: 집합은 같은 값을 중복해서 저장하지 않는다. 따라서 `set([3, 1, 3, 2, 1])`에는 `1`, `2`, `3`이 한 번씩만 남는다. 다만 집합은 입력 순서를 보존하는 자료 구조로 사용하면 안 되며, 원소도 해시 가능한 값이어야 한다. 중복 제거와 정렬은 서로 다른 작업이다.

### 8번

**튜플은 리스트와 마찬가지로 `items[0] = 10`처럼 특정 위치의 원소를 교체할 수 있다.**

정답: X

올바른 문장: 튜플의 특정 위치에 새 원소를 대입하는 연산은 허용되지 않는다.

해설: 튜플은 불변 객체이므로 특정 칸이 가리키는 원소를 대입으로 교체할 수 없다. `items = (1, 2)` 뒤에 `items[0] = 10`을 실행하면 `TypeError`가 발생한다. 단, `items = ([1], 2)`에서 `items[0].append(3)`은 튜플의 칸을 교체하는 것이 아니라 내부 리스트를 수정하므로 가능하다.

### 9번

**`a, b = b, a`는 두 변수의 값을 교환하는 Python 표현이다.**

정답: O

해설: 오른쪽 식의 값들을 먼저 평가한 뒤 왼쪽 변수들에 대입하므로 원래 값이 사라지지 않는다. `a = 3`, `b = 8`일 때 `a, b = b, a`를 실행하면 `a`는 `8`, `b`는 `3`이다. 두 변수에 차례로 `a = b`, `b = a`를 실행하는 것과는 다르다.

### 10번

**`namedtuple`로 만든 객체는 필드 이름으로만 접근할 수 있으며 `item[0]` 같은 index 접근은 불가능하다.**

정답: X

올바른 문장: `namedtuple`로 만든 객체는 필드 이름과 index로 모두 접근할 수 있고, tuple의 값 비교 기능도 사용할 수 있다.

해설: `namedtuple`은 tuple을 기반으로 하므로 이름 접근과 index 접근을 모두 지원한다. `Point = namedtuple("Point", "x y")`와 `p = Point(3, 4)`를 만들면 `p.x`와 `p[0]`은 모두 `3`이다. tuple처럼 항목 순서대로 값도 비교하며, 이름으로 읽을 수 있다는 것이 index 접근을 없앤다는 뜻은 아니다.

## 2. Python 함수와 모듈

### 11번

**함수 정의의 parameter와 함수 호출 시 전달하는 argument는 구별되는 개념이다.**

정답: O

해설: parameter는 함수를 정의할 때 입력을 받도록 적는 변수이고, argument는 호출 시 실제로 전달하는 값이나 식이다. `def add(x, y): ...`의 `x`, `y`는 parameter이다. `add(2, 3)`의 `2`, `3`은 argument이며, 호출 시 두 값이 각각의 parameter에 연결된다.

### 12번

**리스트를 함수에 전달하면 리스트가 자동으로 깊은 복사되므로, 함수에서 원소를 바꿔도 호출한 쪽의 리스트는 바뀌지 않는다.**

정답: X

올바른 문장: 리스트를 함수에 전달한 뒤 함수가 그 리스트의 원소를 바꾸면, 호출한 쪽에서도 변경된 내용을 볼 수 있다.

해설: Python은 함수 호출만으로 리스트를 자동 복사하지 않는다. parameter와 호출자 변수가 같은 리스트 객체를 가리키므로 함수 안의 `items[0] = 99` 같은 변경이 호출자에게도 보인다. 반대로 함수 안에서 `items = [99]`라고 새 리스트를 대입하면 함수의 지역 이름만 다른 객체를 가리키므로 호출자의 원래 리스트는 교체되지 않는다.

### 13번

**함수에서 `return a, b, c`로 반환한 결과는 세 항목을 담은 튜플로 받을 수 있다.**

정답: O

해설: 쉼표로 나열한 `return a, b, c`는 세 항목을 튜플로 묶어 반환한다. 반환값 전체를 한 변수에 받을 수도 있고 `x, y, z = function()`처럼 풀어 받을 수도 있다. 예를 들어 `return 1, 2, 3`의 결과는 `(1, 2, 3)`이며, 세 번 따로 반환하는 동작이 아니다.

### 14번

**`range(start, stop)`은 `stop`을 포함한다.**

정답: X

올바른 문장: `range(start, stop)`은 `stop`을 포함하지 않는다.

해설: `range(start, stop)`은 기본적으로 1씩 증가하며 `stop` 직전까지의 정수를 나타낸다. 따라서 `list(range(2, 5))`는 `[2, 3, 4]`이다. 정수 5까지 포함하려면 이 경우에는 `range(2, 6)`을 사용한다.

### 15번

**`sorted(array)`는 원래 리스트를 직접 정렬하고 반환값으로 `None`을 준다.**

정답: X

올바른 문장: `sorted(array)`는 정렬된 새 리스트를 반환하고 원래 리스트의 순서를 직접 변경하지 않는다.

해설: `sorted()`는 정렬된 새 리스트를 반환한다. `a = [3, 1, 2]`에서 `b = sorted(a)`를 실행하면 `a`는 `[3, 1, 2]`, `b`는 `[1, 2, 3]`이다. 원래 리스트 자체를 정렬하고 `None`을 반환하는 것은 `a.sort()`이다. 따라서 `a = a.sort()`라고 쓰면 `a`가 `None`이 되는 점을 주의한다.

### 16번

**`array.sort(key=lambda item: item.x)`는 리스트 자체를 각 원소의 x값 기준으로 정렬한다.**

정답: O

해설: `list.sort()`는 리스트 자체를 정렬한다. `key=lambda item: item.x`는 각 원소에서 비교에 사용할 x값을 추출한다. x값이 `5, 1, 3`인 원소들은 기본 오름차순에서 `1, 3, 5` 순서로 놓이며, key가 같으면 기존의 상대 순서는 보존된다. 원소 객체의 x값을 수정하는 연산은 아니다.

### 17번

**`if __name__ == "__main__":` 안의 코드는 해당 파일을 다른 파일에서 모듈로 import할 때도 실행된다.**

정답: X

올바른 문장: `if __name__ == "__main__":` 안의 코드는 해당 파일을 모듈로 import하기만 할 때 실행되지 않는다.

해설: 파일을 직접 실행하면 그 파일의 `__name__`은 `"__main__"`이지만 일반적인 import에서는 모듈 이름이 된다. 따라서 조건문 안의 실행 코드는 import만 할 때 실행되지 않는다. 다만 조건문 바깥의 최상위 코드는 최초 import 시 실행될 수 있으므로, import가 파일의 모든 코드를 건너뛴다는 뜻은 아니다.

### 18번

**`import module as alias`는 가져온 모듈을 별칭으로 참조하게 한다.**

정답: O

해설: `import math as m`을 실행하면 가져온 모듈을 `m.sqrt(9)`처럼 참조할 수 있다. 별칭은 현재 코드에서 사용할 이름을 정하는 것이며 원본 모듈 파일의 이름이나 내용을 바꾸지 않는다. 별칭만 가져온 상태에서 원래 이름 `math`가 자동으로 별도 변수로 생긴다고 가정해서도 안 된다.

### 19번

**Quick Sort와 Selection은 목적이 다르므로 하나의 partition 함수를 함께 사용할 수 없다.**

정답: X

올바른 문장: 하나의 모듈에 정의한 partition 함수를 Quick Sort와 Selection에서 함께 사용할 수 있다.

해설: 두 알고리즘은 pivot을 기준으로 원소를 나누고 pivot 위치를 반환받는 과정이 같다. 차이는 그 뒤의 처리이다. Quick Sort는 양쪽을 정렬하고, Quickselect는 찾는 순위가 포함된 한쪽만 탐색한다. 실제 수업 코드도 Selection에서 Quick Sort 모듈의 `partition_random()`을 호출하며, 이 함수는 공통 `partition()`을 재사용한다.

### 20번

**같은 실행 환경에서 동일한 난수 시드와 동일한 난수 호출 순서를 사용하면 실험 데이터를 재현할 수 있다.**

정답: O

해설: 의사난수 생성기는 내부 상태와 정해진 규칙으로 다음 값을 만든다. 같은 실행 환경에서 같은 시드로 시작하고 같은 난수 함수를 같은 순서로 호출하면 같은 결과를 재현할 수 있다. 중간에 난수 호출을 하나 추가하면 이후 결과가 달라질 수 있으며, Python 버전이나 사용한 생성기까지 바뀐 환경에서 모든 결과가 같다는 뜻은 아니다.

## 3. 알고리즘과 복잡도

### 21번

**알고리즘의 정확성과 실행 효율은 서로 구별하여 확인해야 한다.**

정답: O

해설: 정확성은 요구한 답을 구하는지, 효율은 그 답을 구하는 데 시간과 메모리를 얼마나 쓰는지를 뜻한다. 답이 틀린 프로그램이 빨라도 올바른 알고리즘이 되지는 않는다. 반대로 모든 쌍을 검사해 정확한 답을 얻더라도 큰 입력에서는 느릴 수 있으므로, 결과와 비용을 따로 확인해야 한다.

### 22번

**선형 탐색은 배열이 정렬되어 있을 때만 사용할 수 있다.**

정답: X

올바른 문장: 선형 탐색은 정렬되지 않은 배열에서도 사용할 수 있다.

해설: 선형 탐색은 원소를 앞에서부터 하나씩 확인하므로 정렬을 전제로 하지 않는다. `[8, 2, 6]`에서 `2`를 찾을 때 `8`, `2` 순서로 검사하면 찾을 수 있다. 정렬되지 않았기 때문에 현재 값이 목표보다 크다는 이유만으로 나머지를 버릴 수는 없으며, 최악에는 n개를 모두 검사한다.

### 23번

**표준 이진 탐색은 정렬되지 않은 배열에서도 중간 원소와 비교하여 절반을 버리는 방법으로 항상 값을 정확하게 찾는다.**

정답: X

올바른 문장: 이진 탐색으로 값을 찾으려면 탐색 범위가 사용하려는 비교 기준에 맞게 정렬되어 있어야 한다.

해설: 표준 이진 탐색은 중간값과 비교한 뒤 목표가 존재할 수 없는 절반을 버린다. 이 판단은 탐색 구간이 비교 기준에 맞게 정렬되어 있을 때만 성립한다. `[3, 1, 2]`에서 `3`을 찾으며 중간값 `1`보다 크다는 이유로 오른쪽만 남기면, 왼쪽의 `3`을 놓친다.

### 24번

**배열의 최댓값을 한 번의 순회로 찾는 알고리즘은 원소 수 n에 대해 O(n) 시간이 걸린다.**

정답: O

해설: 첫 원소를 현재 최댓값으로 두고 나머지 n - 1개를 한 번씩 비교하면 된다. 원소 수에 비례하는 비교만 하므로 시간복잡도는 O(n)이며, 더 정확한 증가 차수는 Θ(n)이다. 현재 최댓값 하나만 유지하면 되므로 입력 배열을 제외한 추가 공간은 O(1)로 구현할 수 있다.

### 25번

**서로 다른 index의 순서 없는 쌍을 모두 검사하면 쌍의 수는 n(n - 1) / 2개이다.**

정답: O

해설: 서로 다른 두 index를 순서 있게 고르면 n(n - 1)가지이다. 그러나 `(i, j)`와 `(j, i)`가 같은 쌍이므로 2로 나누어 `n(n - 1) / 2`가 된다. 예를 들어 n = 4이면 6쌍이다. 코드에서는 `i < j`인 경우만 확인하면 자기 자신과의 비교와 중복 비교를 피한다.

### 26번

**실행시간이 n²에 비례한다고 볼 수 있는 구간에서는 입력 크기를 두 배로 늘리면 시간이 대략 두 배가 된다.**

정답: X

올바른 문장: 실행시간이 n²에 비례한다고 볼 수 있는 구간에서는 입력 크기를 두 배로 늘리면 시간이 대략 네 배가 된다.

해설: 실행시간을 `T(n) ≈ c·n²`로 보면 `T(2n) ≈ c·(2n)² = 4c·n²`이다. 따라서 입력이 두 배이면 대략 네 배의 시간이 필요하다. 실제 측정에는 상수 비용과 실행 환경 영향도 있으므로 모든 측정에서 정확히 네 배라는 뜻은 아니다.

### 27번

**각각 n번의 연산을 수행하는 두 작업을 차례로 한 번씩 실행하면, 총 연산 횟수는 n²번이다.**

정답: X

올바른 문장: 각각 n번의 연산을 수행하는 두 작업을 차례로 한 번씩 실행하면 총 연산 횟수는 2n번이며, 증가 차수는 Θ(n)이다.

해설: 두 작업을 순서대로 한 번씩 실행하면 횟수를 더하므로 `n + n = 2n`이다. n = 10이면 20번이며 100번이 아니다. n번 반복하는 작업 안에서 다시 n번 작업하는 중첩 구조라야 `n × n`이 된다. 참고로 Big-O는 상한이므로 Θ(n)인 작업도 느슨하게 O(n²)라고 쓸 수 있다. 이 문항은 표기상의 논란을 피하려고 정확한 연산 횟수를 묻는다.

### 28번

**O(n log n)과 O(n²)의 실제 실행시간을 작은 입력 한 번만으로 비교하여 모든 입력 크기의 우열을 단정할 수는 없다.**

정답: O

해설: 점근적 시간복잡도는 입력이 커질 때 비용이 증가하는 추세를 설명한다. 실제 작은 입력에서는 함수 호출, 메모리 할당, 구현 상수 때문에 O(n²) 알고리즘이 더 빠를 수도 있다. 여러 입력 크기와 입력 형태를 확인해야 하며, 작은 입력 한 번의 측정만으로 모든 크기의 우열을 단정할 수 없다.

### 29번

**서로 다른 n개 원소를 비교만으로 정렬하는 알고리즘도 모든 입력에 대해 O(n) 시간에 정렬할 수 있다.**

정답: X

올바른 문장: 서로 다른 n개 원소를 비교만으로 정렬하는 문제의 최악 비교 횟수 하한은 Ω(n log n)이다.

해설: 서로 다른 n개 값의 입력 순서는 n!가지이다. 두 값의 비교 결과로 갈라지는 결정 트리는 이 가능성들을 구별할 만큼 깊어야 하므로 최악 비교 횟수가 적어도 `log₂(n!) = Ω(n log n)`이다. 따라서 비교만 사용하는 정렬이 모든 입력에서 O(n)에 끝날 수는 없다. Counting Sort처럼 값의 범위를 사용하는 정렬에는 이 전제가 그대로 적용되지 않는다.

### 30번

**작은 입력의 답을 직접 구하는 종료 조건은 재귀 알고리즘을 끝내는 데 필요하다.**

정답: O

해설: 재귀는 더 작은 문제로 진행한 뒤 재귀 호출 없이 답을 내는 경우에 도달해야 끝난다. 예를 들어 Merge Sort는 원소가 0개 또는 1개인 구간을 이미 정렬된 것으로 처리할 수 있다. 종료 조건만 적는 것도 충분하지 않고, 재귀 인자가 실제로 그 조건에 가까워지도록 줄어들어야 한다.

## 4. Bubble, Selection, Insertion, Shell Sort

### 31번

**Bubble Sort는 인접한 두 원소의 순서를 비교하고 필요하면 교환한다.**

정답: O

해설: 오름차순 Bubble Sort는 이웃한 두 값이 역순이면 교환한다. `[3, 1, 2]`를 왼쪽부터 검사하면 먼저 `[1, 3, 2]`, 다음에는 `[1, 2, 3]`이 된다. 한 번의 교환에서는 두 이웃의 위치만 바뀌며, 이런 비교를 반복해 큰 값을 뒤로 보낸다.

### 32번

**큰 값을 오른쪽으로 보내는 Bubble Sort에서 한 pass를 끝내면 검사 구간의 최솟값이 그 구간의 맨 오른쪽에 놓인다.**

정답: X

올바른 문장: 큰 값을 오른쪽으로 보내는 Bubble Sort에서 한 pass를 끝내면 검사 구간의 최댓값이 그 구간의 맨 오른쪽에 놓인다.

해설: 문제에서 정한 방향은 큰 값을 오른쪽으로 보내는 방식이므로, 한 pass 후 확정되는 값은 최댓값이다. `[4, 1, 3, 2]`에 한 pass를 적용하면 `[1, 3, 2, 4]`가 되어 `4`가 맨 오른쪽에 놓인다. 앞쪽 `[1, 3, 2]`까지 정렬된 것은 아니므로 추가 pass가 필요하다.

### 33번

**Bubble Sort의 한 pass에서 교환이 한 번도 없었다면 배열은 이미 정렬된 상태이므로 종료할 수 있다.**

정답: O

해설: 검사 구간의 모든 이웃을 확인했는데 교환이 없었다면 역순인 이웃이 없다. 따라서 그 구간은 이미 정렬되어 있으며, 앞선 pass에서 확정한 뒤쪽 구간과 함께 전체 정렬을 마칠 수 있다. 교환 여부를 pass마다 새로 기록해야 하며, 비교 하나에서 교환이 없었다는 이유만으로 끝내는 것은 잘못이다.

### 34번

**Selection Sort는 남은 구간의 최솟값을 찾아 그 구간의 맨 앞에 놓는 과정을 반복할 수 있다.**

정답: O

해설: Selection Sort는 아직 정렬하지 않은 구간에서 최솟값의 위치를 찾은 뒤 그 구간의 첫 위치와 교환한다. `[3, 1, 2]`에서는 첫 단계에 `1`을 앞으로 보내고, 다음에는 남은 `[3, 2]`에서 `2`를 고른다. 이렇게 앞쪽의 정렬 완료 구간이 한 칸씩 늘어난다.

### 35번

**일반적인 Selection Sort는 남은 구간에서 더 작은 값을 발견할 때마다 즉시 교환해야 하므로, 한 바깥 반복에서 반드시 여러 번 교환한다.**

정답: X

올바른 문장: 일반적인 Selection Sort에서 최솟값 탐색은 여러 번의 비교를 하지만, 한 바깥 반복에서의 교환은 최대 한 번이면 된다.

해설: 최솟값을 탐색하는 동안에는 최솟값의 index만 갱신해도 된다. 구간을 모두 확인한 뒤 처음 위치와 최솟값 위치를 한 번 교환하면 된다. 예를 들어 `[5, 4, 3, 2, 1]`에서 후보가 여러 번 바뀌어도 첫 pass의 실제 교환은 `5`와 `1`의 한 번이면 충분하다. 이미 최솟값이 앞에 있으면 교환을 생략할 수도 있다.

### 36번

**Insertion Sort는 이미 정렬된 구간을 활용하지 않고, 매 단계에서 전체 배열의 최솟값을 찾아 맨 앞으로 옮긴다.**

정답: X

올바른 문장: Insertion Sort는 앞쪽의 정렬된 구간에 다음 원소를 삽입하는 방식으로 진행할 수 있다.

해설: 문장의 방식은 Insertion Sort의 핵심과 다르다. Insertion Sort는 앞부분이 정렬되어 있다는 성질을 유지하며 다음 원소 하나를 알맞은 위치에 끼워 넣는다. 예를 들어 앞부분 `[2, 5]`에 다음 값 `3`을 삽입할 때 `5`를 오른쪽으로 밀어 `[2, 3, 5]`로 만든다. 매번 전체 배열의 최솟값을 다시 찾지 않는다.

### 37번

**Insertion Sort에서 삽입할 값을 따로 보관하면 더 큰 원소들을 오른쪽으로 밀고 마지막에 보관한 값을 넣을 수 있다.**

정답: O

해설: 삽입할 값을 먼저 `value`에 저장하면 그 자리를 다른 원소로 덮어써도 원래 값을 잃지 않는다. `[2, 5, 3]`에서는 `3`을 저장하고 `5`를 한 칸 옮긴 다음 빈자리에 `3`을 넣는다. 마지막 대입 위치는 이동이 끝난 비교 위치의 다음 칸인 `position + 1`이다.

### 38번

**이미 오름차순인 입력에서도 불필요한 비교를 멈추는 Insertion Sort는 반드시 Θ(n²)번의 비교를 한다.**

정답: X

올바른 문장: 이미 오름차순인 입력에서 불필요한 비교를 멈추는 Insertion Sort는 O(n) 시간에 동작한다.

해설: 이미 오름차순이면 다음 원소를 이전 원소와 비교하는 즉시 삽입 위치가 결정된다. 각 바깥 반복에서 내부 비교를 곧바로 멈추므로 전체 원소 비교는 대략 n - 1번으로, Θ(n)이다. 반대로 역순 입력에서는 많은 원소를 이동해야 하므로 일반적인 Insertion Sort의 최악은 Θ(n²)이다. 최선과 최악의 입력 조건을 구별해야 한다.

### 39번

**Shell Sort는 gap 간격으로 떨어진 원소들의 부분 배열에 삽입 정렬을 적용할 수 있다.**

정답: O

해설: gap이 3이면 index가 `0, 3, 6, ...`인 그룹, `1, 4, 7, ...`인 그룹 등을 각각 삽입 정렬한다. 큰 gap으로 멀리 떨어진 원소를 먼저 이동시킨 뒤 gap을 줄여 배열을 정돈한다. 같은 gap 그룹 안이 정렬되었다고 다른 그룹 사이까지 정렬된 것은 아니다.

### 40번

**Shell Sort는 마지막 gap을 2로 끝내도 모든 입력에서 배열 전체의 오름차순 정렬을 보장한다.**

정답: X

올바른 문장: Shell Sort에서 마지막 gap을 1로 두어 전체 배열에 삽입 정렬을 수행하면 배열 전체가 정렬된다.

해설: gap이 2이면 짝수 index 그룹과 홀수 index 그룹만 각각 정렬될 수 있다. `[2, 1, 4, 3]`은 짝수 위치의 값 `[2, 4]`와 홀수 위치의 값 `[1, 3]`이 이미 정렬되어 있지만 배열 전체는 정렬되어 있지 않다. 마지막 gap을 1로 두면 모든 원소가 같은 그룹에 들어가므로 전체 정렬을 완성한다.

## 5. Heap Sort

### 41번

**완전 이진 트리의 마지막 level은 오른쪽부터 채워진다.**

정답: X

올바른 문장: 완전 이진 트리의 마지막 level은 왼쪽부터 채워진다.

해설: 완전 이진 트리는 마지막 level을 제외한 모든 level이 차 있고, 마지막 level은 왼쪽부터 빈자리 없이 채워진다. 마지막 level에 오른쪽 자식만 있고 왼쪽 자식이 비어 있다면 완전 이진 트리가 아니다. 이 성질 덕분에 힙의 노드를 배열의 처음부터 연속해서 저장할 수 있다.

### 42번

**0부터 시작하는 배열로 이진 힙을 나타낼 때 index i의 왼쪽 자식 위치는 2i + 1이다.**

정답: O

해설: 0부터 시작하는 배열에서 root는 index 0이고 그 자식은 1, 2이다. 각 level을 왼쪽부터 저장하면 부모 i의 왼쪽 자식은 `2i + 1`이 된다. 예를 들어 i = 2의 왼쪽 자식은 index 5이다. 계산한 index가 현재 힙 크기보다 작을 때만 실제 자식이 존재한다.

### 43번

**0부터 시작하는 배열로 이진 힙을 나타낼 때 index i의 오른쪽 자식 위치는 2i + 1이다.**

정답: X

올바른 문장: 같은 배열 표현에서 index i의 오른쪽 자식 위치는 2i + 2이다.

해설: `2i + 1`은 왼쪽 자식이며 오른쪽 자식은 그 다음 칸인 `2i + 2`이다. i = 1이면 왼쪽 자식은 3, 오른쪽 자식은 4이다. 1부터 시작하는 배열 표현의 공식과 혼동하지 않아야 하며, 오른쪽 자식이 실제로 존재하는지도 힙 크기로 확인해야 한다.

### 44번

**원소가 두 개 이상인 배열 힙에서 자식을 가진 마지막 부모의 index는 `count // 2 - 1`이다.**

정답: O

해설: index i가 부모이려면 최소한 왼쪽 자식 `2i + 1`이 `count`보다 작아야 한다. 이를 만족하는 가장 큰 i가 `count // 2 - 1`이다. count = 6이면 마지막 부모는 2이고 자식 index 5가 존재한다. 그 다음 index 3부터는 leaf이므로 build heap에서 downheap을 시작할 필요가 없다.

### 45번

**Max Heap에서는 각 부모의 값이 존재하는 자식들의 값보다 크거나 같다.**

정답: O

해설: Max Heap의 조건은 모든 부모가 자신의 자식보다 작지 않아야 한다는 것이다. 부모가 9이고 자식이 7, 8이면 조건을 만족하며, 부모와 자식의 값이 같은 것도 허용한다. 형제끼리의 대소 순서까지 정하지는 않으므로 Max Heap 배열이 곧 내림차순 배열인 것은 아니다.

### 46번

**Max Heap의 root에는 힙 전체의 최솟값이 있다.**

정답: X

올바른 문장: Max Heap의 root에는 힙 전체의 최댓값이 있다.

해설: root에서 임의의 자손으로 내려가는 경로를 보면 각 부모는 다음 자식보다 크거나 같다. 따라서 root는 모든 자손보다 크거나 같아 전체 최댓값을 가진다. 전체 최솟값을 root에 두는 것은 Min Heap이다. Max Heap에서 최솟값의 정확한 위치는 root처럼 하나로 정해져 있지 않다.

### 47번

**양쪽 자식 subtree가 이미 Max Heap이면 root에 downheap을 적용하여 해당 tree 전체를 Max Heap으로 만들 수 있다.**

정답: O

해설: 두 자식 subtree가 이미 Max Heap이라면 깨질 수 있는 곳은 현재 root와 그 아래로 이어지는 경로이다. root를 더 큰 자식과 비교해 필요하면 교환하고, 내려간 위치에서 같은 작업을 반복한다. 예를 들어 `[2, 7, 8]`에서는 2와 8을 교환하면 `[8, 7, 2]`가 된다. 자식 subtree가 먼저 힙이어야 한다는 전제가 핵심이다.

### 48번

**마지막 부모부터 root 방향으로 downheap을 적용하는 build heap은 최악에도 O(log n) 시간에 끝난다.**

정답: X

올바른 문장: 마지막 부모부터 root 방향으로 downheap을 적용하는 build heap은 O(n) 시간에 수행할 수 있다.

해설: O(log n)은 downheap 한 번의 최악 비용이지 전체 build heap의 비용이 아니다. 아래쪽 노드는 이동할 높이가 작고, 높은 노드의 수는 적다. 높이 h인 노드의 수가 대략 `n / 2^(h + 1)`이므로 전체 비용을 더하면 `n·Σ(h / 2^(h + 1)) = O(n)`이다. 이처럼 마지막 부모부터 처리하는 bottom-up build heap은 최악 Θ(n)으로 분석하며, 원소를 하나씩 삽입하는 별도 구축 방식과 구별한다.

### 49번

**Heap Sort에서 root를 마지막 원소와 교환하고 힙 크기를 줄이면, 남은 힙은 downheap을 하지 않아도 항상 Max Heap 조건을 만족한다.**

정답: X

올바른 문장: Heap Sort에서 root를 마지막 원소와 교환하고 힙 크기를 줄인 뒤에는, 남은 힙의 Max Heap 조건을 downheap으로 복구해야 할 수 있다.

해설: root에 올라온 값은 원래 마지막 leaf의 값이므로 자식보다 작을 수 있다. Max Heap `[9, 7, 8, 1, 2]`에서 root와 마지막 값을 교환하고 9를 제외하면 남은 구간은 `[2, 7, 8, 1]`이다. root 2가 자식 7, 8보다 작아 힙 조건이 깨진다. root에 downheap을 적용해 복구해야 다음 최댓값도 정확히 꺼낼 수 있다.

### 50번

**일반적인 Heap Sort의 전체 최악 시간복잡도는 O(n log n)이다.**

정답: O

해설: 처음 힙을 만드는 비용은 O(n)이다. 이후 최댓값을 꺼내는 작업을 최대 n - 1번 수행하고, 각 단계에서 힙을 복구하는 데 O(log n)이 걸린다. 합하면 `O(n) + O(n log n) = O(n log n)`이다. 따라서 일반적인 Heap Sort는 최악에도 O(n log n) 시간에 정렬한다.

## 6. Counting Sort와 Radix Sort

### 51번

**Counting Sort는 각 키 값의 등장 횟수를 세어 정렬에 이용한다.**

정답: O

해설: Counting Sort는 원소끼리의 대소 비교 대신 값별 등장 횟수를 활용한다. `[2, 1, 2, 0]`이면 0이 1개, 1이 1개, 2가 2개이다. 이 개수대로 값을 출력하거나 누적 계수로 원소의 위치를 정하면 `[0, 1, 2, 2]`를 얻는다.

### 52번

**Counting Sort의 계수 배열 크기는 입력 원소 수 n만으로 정해지며 키 값의 범위와는 관계없다.**

정답: X

올바른 문장: Counting Sort의 계수 배열 크기는 입력 원소 수뿐 아니라 키 값의 범위에도 영향을 받는다.

해설: 직접 주소 방식의 계수 배열에는 각 가능한 키에 대응하는 칸이 필요하다. 원소가 두 개뿐이어도 값이 `[0, 1000000]`이면 단순 구현은 1000001칸을 준비한다. 반대로 많은 원소가 0부터 9 사이에만 있으면 10칸이면 된다. 입력 수 n과 키 범위 크기 k를 따로 고려해야 한다.

### 53번

**Counting Sort는 n개 원소와 크기 k의 키 범위에 대해 O(n + k) 시간에 구현할 수 있다.**

정답: O

해설: 입력을 읽어 개수를 세는 비용은 O(n), 계수 배열 초기화와 누적합은 O(k), 결과 배치는 O(n)이다. 이를 합하면 O(n + k)이다. 키 범위 k가 입력 수보다 매우 크면 k의 비용이 지배하므로, Counting Sort를 조건 없이 항상 O(n)이라고 부르면 안 된다. k는 서로 다른 키의 개수가 아니라 배열로 표현하는 범위의 크기이다.

### 54번

**Counting Sort는 키의 최솟값을 빼서 index를 보정하더라도 음수 키를 처리할 수 없다.**

정답: X

올바른 문장: 키의 최솟값을 빼서 계수 배열 index로 사용하면 음수나 0이 아닌 최솟값도 처리할 수 있다.

해설: 정수 키의 최솟값을 min_value라고 할 때 `value - min_value`를 index로 사용하면 가장 작은 키가 0에 대응한다. `[-3, -1, -3]`은 index `[0, 2, 0]`으로 세고, 출력할 때 index에 -3을 더해 원래 값으로 복원할 수 있다. 이는 음수를 지원하도록 확장하는 방법이다. 현재 수업의 기본 Counting Sort는 `counts[value]`를 사용하므로 이 보정을 이미 구현했다고 해석하면 안 된다.

### 55번

**누적 계수는 어떤 값 이하의 원소가 모두 몇 개인지를 나타내는 데 사용할 수 있다.**

정답: O

해설: 빈도 배열을 앞에서부터 누적하면 해당 값까지 나온 원소의 총수를 알 수 있다. 값 0, 1, 2의 빈도가 `[1, 2, 1]`이면 누적 계수는 `[1, 3, 4]`이다. 여기서 3은 값이 1 이하인 원소가 세 개라는 뜻이다. 배치 과정에서 계수를 감소시키기 전의 이 누적값은 결과 배열에서 해당 값 구간의 끝 다음 위치로 사용할 수 있다.

### 56번

**LSD Radix Sort는 가장 높은 자릿수부터 가장 낮은 자릿수 방향으로 처리한다.**

정답: X

올바른 문장: LSD Radix Sort는 낮은 자릿수부터 높은 자릿수 방향으로 처리한다.

해설: LSD는 Least Significant Digit의 약자로 가장 낮은 자릿수부터 처리한다. 10진수 정수라면 일의 자리, 십의 자리, 백의 자리 순서이다. 높은 자릿수부터 나누는 방식은 MSD이다. 예를 들어 123의 처리 순서는 LSD에서 3, 2, 1이다.

### 57번

**LSD Radix Sort는 각 자릿수의 정렬이 불안정해도 최종 정렬 결과를 항상 보장한다.**

정답: X

올바른 문장: LSD Radix Sort에서 각 자릿수의 정렬이 안정적이면 앞서 처리한 낮은 자릿수의 상대적인 순서를 필요한 범위에서 보존할 수 있다.

해설: 안정성은 현재 자릿수가 같은 원소들의 이전 순서를 보존한다는 뜻이다. `[12, 11]`을 일의 자리로 정렬하면 `[11, 12]`가 된다. 다음 십의 자리에서 둘 다 1이라는 이유로 이 순서를 뒤집으면 `[12, 11]`이 되어 최종 정렬이 틀린다. 따라서 각 단계의 안정성이 이전 자릿수에서 만든 순서를 보존하는 데 필요하다.

### 58번

**MSD Radix Sort는 높은 자릿수 또는 앞쪽 문자부터 나누고 같은 버킷 안을 재귀적으로 처리할 수 있다.**

정답: O

해설: MSD는 Most Significant Digit의 약자로 먼저 상위 자릿수에 따라 그룹을 나눈다. 문자열이라면 첫 글자로 나누고 같은 첫 글자 버킷에서 둘째 글자를 비교하는 식이다. 예를 들어 `car`, `cat`, `dog`를 나누면 `car`와 `cat`만 같은 c 버킷에서 다음 글자를 계속 확인한다.

### 59번

**길이가 서로 다른 문자열을 MSD 방식으로 정렬할 때도 문자열이 끝났다는 경우를 별도로 구별할 필요가 없다.**

정답: X

올바른 문장: 문자열을 MSD 방식으로 정렬할 때는 문자뿐 아니라 문자열이 끝났다는 경우도 구별해야 한다.

해설: 서로 다른 길이의 문자열은 더 이상 읽을 문자가 없는 경우를 구별해야 한다. `a`와 `ab`는 첫 글자가 같지만 사전순으로는 짧은 `a`가 먼저 온다. 수업 구현은 문자열이 끝났으면 별도의 end 버킷 0을 사용하고, 이 버킷은 더 재귀 호출하지 않는다. 이를 구별하지 않고 다음 문자를 읽으면 범위를 벗어나거나 종료 처리가 잘못될 수 있다.

### 60번

**Counting Sort와 Radix Sort는 키의 범위나 자릿수 정보를 사용하므로 비교 정렬 하한과 모순되지 않는다.**

정답: O

해설: 비교 정렬의 Ω(n log n) 하한은 원소 사이의 비교 결과만으로 순서를 결정하는 모델에 적용된다. Counting Sort는 키를 배열 index로 쓰고, Radix Sort는 각 자릿수나 문자를 직접 읽는다. 따라서 비교 외의 정보를 사용하므로 조건이 맞을 때 더 빠르게 정렬해도 모순이 아니다. 대신 키 범위와 자릿수에 따른 시간·공간 비용을 부담한다.

## 7. Divide and Conquer와 Merge Sort

### 61번

**분할 정복은 문제를 나누고 부분 문제를 해결한 뒤 결과를 결합하는 설계 방법이다.**

정답: O

해설: 분할 정복은 큰 문제를 작은 문제들로 나누고, 작은 문제의 답을 구한 뒤 원래 문제의 답으로 결합한다. Merge Sort에서는 두 구간으로 나누기, 각 구간 정렬하기, 두 정렬 결과 병합하기가 이에 대응한다. 충분히 작은 문제는 더 나누지 않고 직접 처리하는 종료 조건도 필요하다.

### 62번

**양 끝을 포함하는 `[left, right]` 구간의 원소 수는 `right - left`이다.**

정답: X

올바른 문장: 양 끝을 포함하는 `[left, right]` 구간의 원소 수는 `right - left + 1`이다.

해설: 양 끝을 포함하므로 두 index의 차이에 1을 더해야 한다. `[3, 5]`에는 index 3, 4, 5의 세 원소가 있으므로 `5 - 3 + 1 = 3`이다. `right - left`는 끝을 제외하는 `[left, right)` 구간에서 사용하는 길이이다. 이 두 규칙을 섞으면 한 칸이 빠지는 오류가 생긴다.

### 63번

**`mid = (left + right) // 2`일 때 양 끝을 포함하는 `[left, mid]`와 `[mid, right]`로 나누면 원소가 중복되지 않는다.**

정답: X

올바른 문장: `mid = (left + right) // 2`일 때 `[left, mid]`와 `[mid + 1, right]`로 나누면 두 구간의 원소가 중복되지 않는다.

해설: 두 구간이 모두 양 끝을 포함하면 `[left, mid]`와 `[mid, right]`에는 mid가 중복으로 들어간다. 올바른 분할은 `[left, mid]`와 `[mid + 1, right]`이다. 특히 `[0, 1]`을 잘못 나누면 오른쪽이 다시 `[0, 1]`이 되어 문제 크기가 줄어들지 않을 수 있다. 중복뿐 아니라 재귀 종료에도 영향을 준다.

### 64번

**Merge Sort의 병합 단계는 양쪽 입력 구간이 각각 정렬되어 있다는 전제에서 수행한다.**

정답: O

해설: 일반적인 merge는 두 구간의 맨 앞 미처리 원소가 각각 그 구간에서 가장 작다는 사실을 이용한다. 이 전제는 양쪽 구간이 각각 정렬되어 있을 때 성립한다. 예를 들어 `[4, 1]`과 `[2, 3]`에 그대로 병합 절차를 적용하면 1보다 2와 3이 먼저 나올 수 있어 전체 정렬을 보장하지 못한다.

### 65번

**두 정렬된 구간에서 다음 원소를 가리키는 index를 각각 관리하면 병합을 선형 시간에 수행할 수 있다.**

정답: O

해설: 왼쪽과 오른쪽의 다음 원소 index를 각각 하나씩 두고 더 작은 쪽을 결과로 옮긴다. 옮긴 쪽의 index만 앞으로 이동하므로 각 원소는 한 번 결과에 들어간다. 두 구간 길이가 a, b이면 병합 비용은 O(a + b)이며, 매번 남은 원소 전체를 다시 검색할 필요가 없다.

### 66번

**병합 중 한쪽 구간이 소진되면 다른 쪽에 남은 원소는 결과에서 버려도 된다.**

정답: X

올바른 문장: 병합 중 한쪽 구간이 소진되면 다른 쪽에 남은 원소는 순서를 유지하여 결과에 붙일 수 있다.

해설: 정렬 결과에는 입력의 모든 원소가 같은 개수만큼 있어야 한다. 한쪽이 소진되었다고 다른 쪽의 원소를 버리면 데이터가 사라진다. `[1, 3]`과 `[2, 4, 5]`를 병합하다 왼쪽이 소진되면 남은 `[4, 5]`를 순서대로 붙여 `[1, 2, 3, 4, 5]`를 완성한다.

### 67번

**병합 중 값이 같을 때 왼쪽 구간 원소를 먼저 선택하면 원래 순서를 보존하는 안정적인 병합을 만들 수 있다.**

정답: O

해설: 안정적인 정렬은 같은 key를 가진 원소들의 기존 상대 순서를 유지한다. 원래 왼쪽 구간의 원소가 오른쪽 구간의 원소보다 앞에 있었으므로, 동률일 때 왼쪽을 먼저 선택하면 두 구간 사이의 동률 순서를 보존한다. 왼쪽의 `(2, A)`와 오른쪽의 `(2, B)`를 key 2로 비교한다면 A를 먼저 놓는다. 전체 Merge Sort가 안정적이려면 자식 구간의 정렬도 같은 원칙을 지켜야 한다.

### 68번

**각각 정렬된 두 구간에서 왼쪽 최솟값이 오른쪽 최댓값 이하이기만 하면 Merge Sort의 병합을 생략해도 전체가 정렬된다.**

정답: X

올바른 문장: 각각 정렬된 두 구간에서 왼쪽 최댓값이 오른쪽 최솟값 이하이면 실제 병합을 생략할 수 있다.

해설: 왼쪽 최솟값과 오른쪽 최댓값만 비교해서는 두 구간 사이의 역순을 확인할 수 없다. `[1, 8]`과 `[3, 10]`은 `1 <= 10`을 만족하지만 그대로 이어 붙인 `[1, 8, 3, 10]`은 정렬되지 않았다. 각각 정렬된 구간에서 병합을 생략하려면 왼쪽 최댓값이 오른쪽 최솟값 이하여야 한다. 배열에서는 `array[mid] <= array[mid + 1]`인지 확인하는 조건이다.

### 69번

**작은 구간을 Insertion Sort로 처리하는 것은 Merge Sort에 적용할 수 있는 혼합 정렬 전략이다.**

정답: O

해설: 작은 구간에서는 재귀 호출과 임시 배열을 만드는 비용이 상대적으로 크게 느껴질 수 있다. 정해진 작은 크기 이하를 Insertion Sort로 정렬하고, 큰 구간만 분할·병합하는 방식이 가능하다. 현재 수업 코드도 원소가 4개 이하인 구간을 Insertion Sort로 처리한다. 기준 크기를 고정된 상수로 유지하면 Merge Sort의 전체 최악 O(n log n) 차수는 유지된다.

### 70번

**균형 있게 나누고 각 단계에서 선형 시간에 병합하는 Merge Sort는 재귀 깊이가 O(log n)이므로 전체 최악 시간복잡도도 O(log n)이다.**

정답: X

올바른 문장: 균형 있게 나누고 각 단계에서 선형 시간에 병합하는 Merge Sort의 최악 시간복잡도는 O(n log n)이다.

해설: 재귀 깊이는 호출이 쌓이는 단계 수이지 전체 작업량이 아니다. 같은 깊이에 있는 모든 구간의 길이를 합하면 n이고, 이 구간들을 병합하는 총비용은 O(n)이다. 이러한 level이 O(log n)개이므로 전체는 O(n log n)이다. 점화식으로 쓰면 `T(n) = 2T(n/2) + Θ(n)`이며, 표준 Merge Sort의 최악 증가 차수는 Θ(n log n)이다.

## 8. Quick Sort와 Pivot 선택

### 71번

**partition을 한 번 끝내면 pivot의 위치뿐 아니라 pivot 양쪽 구간 내부의 정렬도 모두 완료된다.**

정답: X

올바른 문장: partition을 끝냈다고 해서 pivot 양쪽의 원소들이 각각 정렬된 것은 아니다.

해설: partition은 pivot을 기준으로 왼쪽과 오른쪽에 있어야 할 값들을 나눌 뿐, 각 구간 내부까지 정렬하지 않는다. pivot이 4이면 `[2, 3, 1, 4, 7, 6, 5]`는 왼쪽이 모두 4 이하이고 오른쪽이 모두 4보다 커서 수업의 분할 조건을 만족한다. 그러나 `[2, 3, 1]`과 `[7, 6, 5]`는 정렬되지 않았다. 그래서 Quick Sort는 양쪽 구간을 다시 처리한다.

### 72번

**수업의 partition 구현은 종료 후 pivot 왼쪽에 pivot 이하인 값을, 오른쪽에 pivot보다 큰 값을 둔다.**

정답: O

해설: 수업의 `partition()`에서 왼쪽 탐색은 pivot보다 큰 값을 만나면 멈추고, 오른쪽 탐색은 pivot 이하의 값을 만나면 멈춘다. 잘못된 쪽의 두 원소를 교환한 뒤 마지막으로 pivot을 경계에 놓는다. 결과적으로 pivot 왼쪽은 `<= pivot`, 오른쪽은 `> pivot`이 된다. 같은 값이 어느 쪽으로 가는지는 partition 구현에 따라 달라지므로 다른 구현에 이 조건을 그대로 적용하면 안 된다.

### 73번

**partition이 반환한 pivot index를 k라고 하면, Quick Sort는 확정된 pivot을 제외한 양쪽 구간을 재귀적으로 정렬할 수 있다.**

정답: O

해설: 수업 방식의 partition은 반환한 index k에 pivot을 놓고 그 양쪽의 대소 관계를 만족시킨다. 따라서 pivot 자체를 다시 정렬할 필요 없이 `[left, k - 1]`과 `[k + 1, right]`를 처리한다. 확정된 pivot을 재귀 범위에 계속 포함하면 문제 크기가 줄어들지 않는 상황이 생길 수 있다. pivot의 최종 위치를 반환하지 않는 다른 partition 변형과는 구별해야 한다.

### 74번

**무작위 pivot을 선택하는 Quick Sort는 모든 실행에서 최악 O(n log n) 시간을 보장한다.**

정답: X

올바른 문장: pivot 선택으로 매우 불균형한 분할이 반복되면 Quick Sort는 최악 O(n²) 시간이 걸릴 수 있다.

해설: 무작위 선택은 나쁜 분할이 반복될 가능성을 낮추지만, 그 가능성을 없애지는 않는다. 매번 최솟값이나 최댓값이 선택되면 구간 크기가 한 개씩만 줄고 분할 비용이 `n + (n - 1) + ... + 1`처럼 쌓여 Θ(n²)이 될 수 있다. 서로 다른 키를 균등한 무작위 pivot으로 처리하는 Quick Sort의 기대 O(n log n)과 모든 실행의 최악 보장은 다르다.

### 75번

**무작위 pivot 선택은 특정한 입력 순서에 대한 의존을 줄이는 데 사용할 수 있다.**

정답: O

해설: 항상 첫 원소를 pivot으로 고르면 이미 정렬된 입력처럼 특정 순서에서 편향된 분할이 반복될 수 있다. 무작위 위치를 선택하면 입력 순서만으로 매번 같은 나쁜 pivot이 결정되는 의존을 줄인다. 다만 중복 키가 많아 발생하는 편향까지 자동으로 해결하는 것은 아니다. 수업의 두 갈래 partition에서는 값이 모두 같으면 어느 위치를 골라도 같은 편으로 몰릴 수 있다.

### 76번

**Median-of-three는 세 후보의 산술평균을 계산하여 그 값을 pivot으로 사용하는 방법이다.**

정답: X

올바른 문장: Median-of-three는 세 후보 값 중 중앙값을 pivot으로 선택하는 방법이다.

해설: Median은 중앙값이고 mean은 산술평균이다. 후보가 `[2, 4, 100]`이면 중앙값은 실제 후보 중 하나인 4이지만 산술평균은 `106 / 3`이다. Median-of-three는 세 후보를 값 순서로 비교하여 가운데 후보를 고른다. 배열 전체의 중앙값을 정확히 계산한다는 뜻도 아니다.

### 77번

**Tukey의 ninther는 세 묶음에서 각각 중앙값을 고른 뒤 그 세 값의 중앙값을 고르는 표본 선택 방법이다.**

정답: O

해설: 9개 표본을 세 개씩 세 묶음으로 나누고, 각 묶음에서 중앙값 하나를 고른다. 그런 다음 선택한 세 중앙값의 중앙값을 최종 pivot 후보로 사용한다. 즉 median-of-three를 각 묶음에 한 번씩, 그 결과에 한 번 더 적용하는 방식이다. 배열 전체를 정렬하지 않고 중앙에 가까운 후보를 찾기 위한 표본 전략이다.

### 78번

**Ninther로 선택한 값은 9개 표본 전체를 정렬했을 때의 정확한 중앙값과 반드시 일치한다.**

정답: X

올바른 문장: Ninther로 선택한 값이 9개 표본 전체의 정확한 중앙값과 반드시 일치하는 것은 아니다.

해설: 중앙값들의 중앙값은 전체 표본의 정확한 중앙값과 다를 수 있다. 묶음이 `[1, 2, 9]`, `[3, 4, 8]`, `[5, 6, 7]`이면 각각의 중앙값은 2, 4, 6이고 ninther는 4이다. 그러나 9개 값 전체는 1부터 9까지이므로 정확한 중앙값은 다섯 번째 값 5이다. Ninther를 정확한 median-of-nine과 동일하게 생각하면 안 된다.

### 79번

**pivot을 고를 때 사용하는 표본 수를 늘리면 선택 비용과 관계없이 작은 구간에서도 항상 실행시간이 줄어든다.**

정답: X

올바른 문장: 더 많은 표본을 사용하는 pivot 선택에는 추가 비용이 있으므로 작은 구간에서 항상 유리하다고 할 수는 없다.

해설: 표본을 더 많이 비교하면 좋은 pivot을 고를 가능성이 높아질 수 있지만, pivot 선택 자체에 추가 비교 비용이 든다. 작은 구간에서는 분할 개선으로 아끼는 비용보다 이 추가 비용이 클 수 있다. 실제 수업 구현도 일정 크기 미만에서는 ninther 대신 median-of-three를 사용한다. 실행시간은 선택 비용과 이후 분할 비용을 함께 판단해야 한다.

### 80번

**작은 구간은 partition하지 않고 남긴 뒤 마지막에 전체 배열을 Insertion Sort로 마무리하는 Quick Sort를 구현할 수 있다.**

정답: O

해설: 큰 구간만 partition하면 서로 다른 작은 구간 사이의 대소 관계는 정리되지만 작은 구간 내부에는 역순이 남을 수 있다. 이후 전체 배열에 Insertion Sort를 적용하여 이 역순을 마무리한다. 현재 수업 코드의 `quick_sort_range()`는 4개 이하 구간을 남겨 두고 `quick_sort()`가 마지막에 전체 삽입 정렬을 실행한다. 마지막 단계를 빼면 작은 구간 내부가 정렬되지 않을 수 있다.

## 9. Selection과 Quickselect

### 81번

**Selection 문제는 전체 정렬이 아니라 특정 순위의 값을 찾는 문제이다.**

정답: O

해설: Selection은 r번째로 작은 값처럼 특정 순위 하나를 구하는 문제이다. `[9, 1, 5, 3]`에서 두 번째로 작은 값은 3이며, 그 사실을 알려면 나머지 값의 전체 정렬 순서를 결과로 만들 필요는 없다. 전체 정렬 후 해당 위치를 읽는 방법도 가능하지만 Quickselect처럼 필요한 구간만 처리하는 방법을 사용할 수 있다.

### 82번

**Selection 문제와 Selection Sort는 이름만 다를 뿐, 둘 다 배열 전체를 정렬해야만 해결되는 동일한 문제이다.**

정답: X

올바른 문장: Selection 문제와 Selection Sort는 서로 다른 개념이다.

해설: Selection 문제는 특정 순위의 값을 찾는 목표이고, Selection Sort는 배열 전체를 정렬하는 알고리즘이다. 예를 들어 최솟값 하나를 찾는 작업은 Selection 문제이며 한 번의 순회로도 해결된다. Selection Sort는 이와 같은 최솟값 선택을 남은 구간에 반복하여 전체 순서를 만든다. 이름이 비슷해도 목표와 전체 비용이 다르다.

### 83번

**Quickselect는 partition을 마친 뒤 pivot의 왼쪽과 오른쪽 구간을 모두 재귀적으로 탐색해야 한다.**

정답: X

올바른 문장: Quickselect는 partition 결과를 이용해 답이 있는 한쪽 구간만 계속 탐색할 수 있다.

해설: partition 후 pivot의 현재 구간 내 순위를 알면 답이 왼쪽인지, pivot인지, 오른쪽인지 판단할 수 있다. 찾는 순위가 pivot 순위보다 작으면 왼쪽만, 크면 오른쪽만 남긴다. pivot 순위와 같으면 바로 종료한다. 양쪽을 모두 재귀 처리하는 것은 Quick Sort의 방식이며 Quickselect에는 불필요하다.

### 84번

**양 끝 포함 `[left, right]`에서 pivot index가 k이면 pivot의 현재 구간 내 1부터 시작하는 순위는 `k - left`이다.**

정답: X

올바른 문장: 양 끝 포함 `[left, right]`에서 pivot index가 k이면 pivot은 현재 구간의 `k - left + 1`번째로 작은 값에 해당한다.

해설: index의 차이 `k - left`는 pivot 앞에 놓인 원소 수이다. 순위는 1부터 시작하므로 pivot 자체까지 포함해 `k - left + 1`을 사용한다. left = 3, k = 5라면 index 3, 4, 5 중 세 번째이므로 순위는 3이다. 배열 전체 index와 현재 구간의 상대 순위를 혼동하지 않아야 한다.

### 85번

**찾는 순위가 pivot 순위와 같으면 pivot의 값을 바로 답으로 반환할 수 있다.**

정답: O

해설: partition 후 pivot 앞에는 현재 구간에서 pivot보다 작거나 같은 원소가 정해진 수만큼 있고, 오른쪽에는 더 큰 값이 놓인다. 이때 계산한 pivot 순위가 원하는 순위와 같으면 그 값이 답이다. 찾는 순위가 4이고 pivot 순위도 4라면 `array[k]`를 반환하며, 나머지 구간은 정렬할 필요가 없다.

### 86번

**찾는 순위가 pivot 순위보다 작으면 왼쪽 구간에서 같은 순위를 찾을 수 있다.**

정답: O

해설: 왼쪽 구간으로 이동할 때는 현재 구간의 앞쪽에서 어떤 원소도 제거하지 않는다. 따라서 그 구간에서 찾는 상대 순위도 그대로이다. pivot 순위가 5이고 원하는 순위가 2이면 왼쪽 네 원소 중 두 번째를 찾는다. 오른쪽으로 이동할 때와 달리 순위에서 pivot 순위를 빼지 않는다.

### 87번

**찾는 순위가 pivot 순위보다 크면 오른쪽 구간에서도 원래 순위를 그대로 찾아야 한다.**

정답: X

올바른 문장: 찾는 순위가 pivot 순위보다 크면 오른쪽 구간에서는 원래 순위에서 pivot 순위를 뺀 순위를 찾아야 한다.

해설: 오른쪽으로 이동하면 pivot과 왼쪽의 원소들이 새 탐색 범위에서 제외된다. 이 원소 수가 pivot 순위이므로 새 상대 순위는 `rank - pivot_rank`이다. 예를 들어 전체에서 다섯 번째 값을 찾고 pivot이 세 번째이면 오른쪽 구간에서는 두 번째를 찾는다. 원래 순위 5를 그대로 쓰면 잘못된 값을 찾거나 범위를 벗어난다.

### 88번

**중복값이 있어도 정렬 결과의 각 위치에 순위를 부여하면 n번째로 작은 값을 정의할 수 있다.**

정답: O

해설: 중복값도 각각 하나의 원소로 세면 정렬 결과의 위치마다 순위를 줄 수 있다. `[2, 2, 5]`에서 첫 번째와 두 번째로 작은 값은 모두 2이고 세 번째는 5이다. 서로 다른 값만 추려 순위를 매기는 문제와는 구별해야 한다. n번째 값은 전체 원소 수가 n 이상일 때 정의된다.

### 89번

**키가 서로 다른 입력에서 현재 구간의 각 원소를 같은 확률로 pivot으로 고르는 Quickselect의 기대 시간복잡도는 O(n)이다.**

정답: O

해설: 키가 서로 다르고 각 원소를 같은 확률로 pivot으로 고르면, 반복적으로 충분히 큰 부분을 버릴 가능성이 있어 기대 총 작업량이 선형이 된다. 직관적으로 균형 있게 줄어드는 경우의 비용은 `n + n/2 + n/4 + ... < 2n`이며, 기대 O(n)이 모든 단계에서 정확히 절반으로 줄어든다는 뜻은 아니다. 불운한 선택이 반복되는 최악의 경우는 O(n²)이다. 또한 수업의 `<=`/`>` 두 갈래 partition에서는 모든 값이 같고 낮은 순위를 찾을 때 n - 1개씩 남을 수 있으므로, 중복 입력까지 같은 기대 보장을 적용하려면 동률을 별도 처리하는 등의 조건이 필요하다.

### 90번

**Quickselect가 원하는 순위의 값을 반환했다면 배열 전체도 반드시 오름차순으로 정렬되어 있다.**

정답: X

올바른 문장: Quickselect가 답을 찾은 뒤에도 배열의 나머지 부분은 완전히 정렬되지 않은 상태일 수 있다.

해설: Quickselect는 원하는 순위의 값만 확정하면 끝난다. pivot이 4이고 분할 결과가 `[2, 3, 1, 4, 7, 6, 5]`일 때 네 번째 값을 찾는다면 즉시 4를 반환할 수 있다. 그러나 좌우 구간은 모두 정렬되어 있지 않다. 반환값의 정확성과 배열 전체의 정렬 여부는 별도로 판단해야 한다.

## 10. Closest Pair

### 91번

**Closest Pair는 평면의 점들 중 거리가 가장 먼 두 점을 찾는 문제이다.**

정답: X

올바른 문장: Closest Pair는 평면의 점들 중 거리가 가장 짧은 두 점을 찾는 문제이다.

해설: Closest Pair는 가장 가까운 두 점을 찾는 문제이다. 유클리드 거리라면 두 점 사이 거리는 `sqrt((x1 - x2)² + (y1 - y2)²)`로 계산하고 그 값이 최소인 쌍을 고른다. 가장 먼 쌍을 찾는 것은 다른 문제이다. 서로 다른 두 점이 같은 좌표에 있으면 최근접 거리는 0일 수 있다.

### 92번

**x좌표순으로 정렬된 점들을 좌우로 나누면 두 부분 내부의 최근접 쌍만 비교해도 전체 최근접 쌍을 항상 구할 수 있다.**

정답: X

올바른 문장: x좌표순으로 정렬된 점들을 좌우로 나눠도 두 부분의 최근접 쌍만 비교해서는 전체 정답이 보장되지 않는다.

해설: 전체 최근접 쌍은 왼쪽에 하나, 오른쪽에 하나인 경계 쌍일 수 있다. x축 위의 점 `(-10, 0)`, `(-1, 0)`, `(1, 0)`, `(10, 0)`을 두 개씩 나누면 양쪽 내부 거리는 모두 9이다. 하지만 경계를 가로지르는 `(-1, 0)`과 `(1, 0)`의 거리는 2이다. 따라서 두 내부 결과뿐 아니라 경계 주변 후보도 검사해야 한다.

### 93번

**좌우 내부의 최소거리 중 작은 값을 d라 하면, 더 가까운 경계 쌍의 두 점은 분할선에서 가로 거리 d 미만인 strip에 모두 포함된다.**

정답: O

해설: 분할선이 두 구간 사이에 있을 때, 서로 다른 편의 두 점 중 하나라도 분할선에서 가로로 d 이상 떨어져 있으면 두 점의 가로 거리부터 d 이상이다. 유클리드 거리는 가로 거리보다 작을 수 없으므로 기존 답 d를 개선하지 못한다. 따라서 더 가까운 경계 쌍을 찾을 때는 양쪽 모두 분할선에서 d 미만인 strip 안의 점만 검사하면 된다. d가 0이면 더 작은 거리는 없으므로 개선할 경계 쌍도 없다.

### 94번

**같은 x좌표의 점들은 항상 같은 편에 속하므로 수업의 Closest Pair 구현에서는 x값만으로 좌우 소속을 구별해도 된다.**

정답: X

올바른 문장: 같은 x좌표의 점이 다른 편에 속할 수 있으므로 수업 구현에서는 x값이 아니라 배열 index로 편을 구별한다.

해설: x순 배열을 원소 수 기준으로 반씩 나누면 같은 x좌표를 가진 점들이 경계 양쪽에 나뉠 수 있다. x값만으로 분류하면 재귀 구간과 y순 목록의 소속이 어긋날 수 있다. 수업 구현은 index가 `mid` 이하이면 왼쪽, 크면 오른쪽으로 판별한다. 같은 x값을 가진 점이라도 원래 배열 index는 달라 소속을 정확히 유지할 수 있다.

### 95번

**두 점의 y좌표 차이가 현재 최소거리 이상이어도 x좌표 차이가 충분히 작으면 실제 유클리드 거리는 현재 최소거리보다 작아질 수 있다.**

정답: X

올바른 문장: strip을 y순으로 탐색할 때 두 점의 y좌표 차이가 현재 최소거리 이상이면 실제 거리도 현재 최소거리 이상이다.

해설: 유클리드 거리 `sqrt(dx² + dy²)`는 항상 `abs(dy)` 이상이다. 따라서 `abs(dy) >= d`이면 dx가 0이어도 실제 거리는 d 이상이다. 예를 들어 d = 5, dy = 6이면 x좌표가 같을 때도 거리는 6이므로 현재 답보다 가까울 수 없다. x 차이가 작다고 y 차이를 상쇄할 수는 없다.

### 96번

**y순 탐색에서 현재 후보와의 y좌표 차이가 최소거리 이상이면 이후 후보도 더 가까울 수 없어 안쪽 반복을 끝낼 수 있다.**

정답: O

해설: strip을 y 오름차순으로 놓고 현재 점 뒤쪽의 후보를 검사하면 후보들의 y 차이는 줄어들지 않는다. 어떤 후보에서 `dy >= best_distance`가 되면 이후 후보도 모두 현재 답보다 가까울 수 없다. 그러므로 해당 현재 점에 대한 안쪽 반복을 `break`할 수 있다. 바깥 반복까지 끝내는 뜻은 아니며, y순 정렬이 없다면 이후 후보에 같은 판단을 적용할 수 없다.

### 97번

**같은 편의 쌍을 제외하기 전에 y좌표 차이를 검사하면 어느 편의 후보에서든 조기 종료 조건을 활용할 수 있다.**

정답: O

해설: y 차이에 따른 종료 조건은 두 점이 같은 편인지 다른 편인지와 무관하게 성립한다. 따라서 y 차이를 먼저 확인하면 같은 편의 먼 후보에서도 즉시 안쪽 탐색을 끝낼 수 있다. 반대로 같은 편이라는 이유로 먼저 `continue`하면 이미 끝낼 수 있었던 비교를 계속할 수 있다. 같은 편의 쌍은 재귀에서 처리했으므로 실제 거리 계산을 생략하되, 종료 조건은 먼저 활용하는 것이다.

### 98번

**최초 y순 index 목록을 앞에서부터 읽어 좌우에 나누어도 각 자식 목록의 y순은 깨지므로, 재귀 호출 전에 반드시 다시 정렬해야 한다.**

정답: X

올바른 문장: 최초 y순 index 목록을 순서대로 좌우에 나누면 각 자식 목록의 y순도 유지된다.

해설: 정렬된 목록을 앞에서부터 읽으며 조건에 맞는 원소만 골라 내면 선택된 원소들의 상대 순서는 유지된다. 예를 들어 y값이 `[1, 3, 4, 8]`인 목록에서 좌우 소속에 따라 `[1, 4]`와 `[3, 8]`로 나누어도 둘 다 y순이다. 수업의 `left_y`, `right_y`는 이 원리를 사용하므로 매 재귀 호출에서 다시 정렬할 필요가 없다.

### 99번

**매 재귀 구간에서 strip을 다시 y순으로 정렬하고 그 뒤의 후보 탐색을 선형 시간에 수행하는 Closest Pair는 최악 O(n log² n) 시간에 구현할 수 있다.**

정답: O

해설: 크기 m인 재귀 구간에서 strip의 크기가 최대 m이면 다시 정렬하는 데 O(m log m)이 들 수 있다. 그 뒤 후보 탐색이 O(m)이라도 정렬 비용은 남는다. 전체를 균형 있게 나누면 `T(n) = 2T(n/2) + O(n log n)`으로 분석하여 O(n log² n) 상한을 얻는다. 이는 strip을 매번 정렬하는 버전의 분석이며, 미리 만든 y순 목록을 나누어 전달하는 현재 구현과 구별한다.

### 100번

**최초에 y순으로 정렬한 목록을 재귀 구간에 나눠 전달하고 각 단계의 결합을 선형 시간에 수행하면 Closest Pair를 O(n log n) 시간에 구현할 수 있다.**

정답: O

해설: 처음 x순과 y순 목록을 만드는 데 O(n log n)이 들고, 이후 각 재귀 구간에서는 y순 index 분배와 strip 수집을 선형 시간에 처리할 수 있다. 각 편 내부의 최소거리가 d 이상이라는 성질 때문에 strip의 가까운 y 범위에 놓일 수 있는 후보 수는 점 하나당 상수 개로 제한되어 탐색도 선형으로 분석된다. 따라서 `T(n) = 2T(n/2) + O(n) = O(n log n)`이다. 이는 평면의 유클리드 거리를 이용한 알고리즘 분석이며 시각화 대기·연출 비용은 포함하지 않는다.
